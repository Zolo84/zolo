# Методика реверсу

## Правила
1. **Жодних файлів гри в репозиторії** — ні ресурсів, ні виконуваних файлів, ні дампів, ні
   дизасембльованого коду. Тестові дані — тільки синтетичні, створені вручну.
2. Двигун читає дані з легальної копії користувача (Steam/GOG). Реверс заради сумісності;
   у репозиторій потрапляє лише власний код і документація форматів/поведінки.
3. Кожна гіпотеза про формат чи правило отримує статус у `docs/formats.md` і тест.

## Порядок роботи
1. **Інвентаризація:** `dh-tool scan <game-dir>` — що за файли, скільки, чи все текстове парситься.
2. **Текстові дані** (більша частина гри): моделі в `dh-data`, звірка з поведінкою гри.
3. **Бінарні формати:** `dh-tool probe` → гіпотеза про структуру → `hexdump` для перевірки →
   парсер у `dh-data` → тест на синтетичному файлі.
4. **Логіка гри:** Ghidra (безкоштовна) по `DarkestHour.exe` (32-bit x86, PE). Точки входу для пошуку:
   рядки-ключі з файлів даних (`"ownedprovinces"`, `"ai_chance"` тощо) → функції, що їх читають →
   структури в пам'яті → код, що їх використовує щодня/щогодини.
5. **Валідація:** запустити оригінал і `dh-tool sim` з тим самим сценарієм, порівняти сейви
   через N днів. Розбіжності — це наступні задачі.

## Корисні інструменти
- Ghidra, x64dbg (налагодження 32-bit процесу), ImHex (шаблони бінарних структур)
- Wine/Proton для запуску оригіналу на Linux поруч із нашим двигуном
