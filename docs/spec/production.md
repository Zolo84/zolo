# Специфікація: черга виробництва (DH 1.05.1)

Позначки: ✅ простежено в коді; 🔎 частково/непрямо; ❓ відкрите. Адреси — VA (база 0x400000). `economy[n]`,
`country[n]` — 1-based позиції чисел у секціях ванільного `db/misc.txt`. Країна — `C`, елемент черги — `E`.

**Статус перевірки.** Формули §2–§5 і приклад §7 незалежно виведено вдруге за дизасемблером (§10): спростовано
одне твердження (перерахунок вартості й днів — щогодини, а не о 00:00) і одне уточнено (штраф інфраструктури
губить і ШІ); приклад Німеччини 1936 збігся до біта за точності x87 24, 53 і 64 біт. Модернізація (§6) перевірена
лише частково. Реалізація — `dh-data::production`, `dh-sim::production` (§8).

## 1. Елемент черги ✅

Черга — двозв'язний список у країні (`C+0x3B7E` голова, `+0x3B82` хвіст, `+0x3B86` кількість). Новий елемент іде в
кінець; ШІ може поставити елемент на початок, передавши від'ємну вартість IC у команді.

Чотири види на спільній основі: **будівля провінції**, **конвой** (транспорти або ескорти), **дивізія** (до 5
бригад) і **бригада** (приєднання до наявної дивізії). Поля (у дужках — ключ сценарію/збереження):

| поле | ключ | зміст |
|---|---|---|
| ім'я, ID | `name`, `id` | |
| провінція | `location` | для будівель; 0 — «без провінції» |
| дата | `date` | дата завершення поточної одиниці (для інтерфейсу) |
| днів | `days` | днів до кінця (інтерфейс, збереження) |
| **днів на одиницю** | `days_for_first` | час однієї одиниці без gearing |
| **IC на добу** | `cost` | |
| **розмір серії / готово** | `size` / `done` | |
| готові нерозміщені | `state` | будівлі без провінції, конвої |
| **чекає людських ресурсів** | `halted` | |
| **накопичувач безперервності** | `progress` | +1.2·frac на добу, −1 за зараховану добу, стеля 3 |
| частка фінансування | — | frac останньої доби |
| **прогрес одиниці** | `total_progress` | 0..1 (значення > 1.5 у файлі — у днях) |
| **людські ресурси на одиницю** | `manpower` | |
| **gearing** | `gearing_bonus` | частка скорочення часу |
| `speed` | `speed` | лише записується; читача не знайдено ❓ |
| прапорці | `upgrade`, `new_model`, `unitcost` | модернізувати модель після кожної одиниці; ШІ щодня піднімає моделі; людина бере щогодинний перерахунок вартості |
| вид | `type` | дивізія/бригада — тип юніта; будівля — індекс 1..10; конвой — 0 транспорт, 1 ескорт |
| модель, бригади | `model`, `extra`, `brigade_model`, `extra1..4`, `brigade_model1..4` | |

Окремих полів «креслення» чи «пауза» немає; пауза — це очікування людських ресурсів.

## 2. Дні, IC на добу й людські ресурси ✅

### 2.1 Джерела
* **Модель** (units.md §17): `cost` (IC на добу), `buildtime` (дні, ціле), `manpower`.
* **Технологічні дельти країни** на тип (дивізії й бригади окремо): додаються до `cost`, `buildtime`, `manpower`
  моделі. Команди технологій `build_cost`, `build_time`, `manpower` з `relative` беруть відсоток від **моделі 0**
  типу (не від поточної): «−10%» означає однакову абсолютну знижку для всіх моделей типу. `build_time` округлюється
  до цілого (half-even).
* **Міністри** — множники TIME і COST на тип дивізії, тип бригади й вид будівлі (ministers.md).
* **Політика**: `MODIFIER_PRODUCTION_TIME`, `MODIFIER_PRODUCTION_COST`, `MODIFIER_GEARING_BONUS` (clamp(1 + Σ,
  0.01, 10)).
* **misc**: `economy[8]` 0.65 — межа gearing; `economy[9]` 0.05 — крок gearing і серійної знижки.
* Складність INDUSTRY, креслення й «практичні» навички у формули **не входять**.

### 2.2 Дні серії з `n` одиниць (`0x466B00`)
```
T  := f32(час_моделі_з_дельтою · міністр TIME[тип])
людина з бригадою в слоті 0: T := max(T, час бригади слоту 0 · міністр TIME[тип бригади])   (ШІ — ні)
T1 := PRODUCTION_TIME · T
мінімум := 1 − GEARING_BONUS + economy[8]                   // ваніль із нейтральною політикою — 0.65
усього := T1 + Σ_{k=1..n−1} max(1 − k·economy[9], мінімум) · T1
дні := округлення_half-even(max(1, усього))
```
Бригада (`0x466FA0`) — те саме з її моделлю й міністром, без порівняння. Будівля (`0x467070`): `T1 = buildtime
таблиці · модифікатор будівель країни · PRODUCTION_TIME · міністр TIME[вид]`; для фабрики IC серійної знижки
**немає**. Конвой (`0x467130`): `T1 = buildtime · модифікатор конвоїв країни · PRODUCTION_TIME · міністр TIME`
(таблиця міністрів дивізій: ескорт — як есмінець, транспорт — як транспорт).

### 2.3 IC на добу
* Дивізія без бригад (`0x467200`): `max(0, вартість_з_дельтою · міністр COST · PRODUCTION_COST)`.
* Бригада (`0x467260`): так само з її моделлю.
* Будівля (`0x4672C0`): `cost таблиці · міністр COST[вид]` — без політики.
* Конвой (`0x4672E0`): `cost · міністр COST` — без політики.
* Дивізія з бригадами (`0x466C20`): **ШІ платить лише за дивізію**. Людина: сумарна вартість (IC·дні) дивізії й
  усіх бригад розтягується на найдовший з їхніх часів: якщо дивізія будується довше — `c_д + Σ(c_б·d_б)/D_д`,
  інакше `(D_д·c_д + Σ c_б·d_б)/max d_б`.

### 2.4 Людські ресурси на одиницю (`0x467310`)
`(max(0.001, manpower моделі з дельтою) + manpower бригади слоту 0) · стеля міцності типу · 0.01`. Стеля міцності
типу (`C+0x40A2`) — 100 за замовчуванням; її задає блок сценарію країни і вона ж обмежує міцність нової дивізії.
При завантаженні сценарію до цього додаються людські ресурси бригад 1..4.

### 2.5 Перерахунок — щогодини (`0x483D70`)
Щогодини для кожного елемента рахуються нові дні й IC на добу за §2.2–§2.3 (для однієї одиниці):
* **ШІ** бере нові значення лише якщо вони **менші** за поточні;
* **людина** з `unitcost` бере нові значення завжди (з `unitcost = 0` — ніколи).
У тій самій годинній обробці дивізії на стапелі з ненульовим прогресом і нерозгорнуті юніти пулу додають
споживання припасів у столиці (`0x44CCB0`) 🔎.

## 3. Добовий прогрес ✅

### 3.1 Порядок у добовому обробнику (лише з правилом `production`)
1. **Завершення будівель**, що дійшли до прогресу 1 учора (будівля ставиться наступного дня): якщо провінція
   придатна — команда розміщення; ШІ інакше ставить у випадкову придатну контрольовану провінцію; у людини
   непридатна провінція — одиниця **губиться**. Цей крок іде навіть без правила `production`.
2. Елементи, що чекають людських ресурсів: якщо запас ≥ потрібного — списати й зняти очікування.
3. Авто-повзунок гравця.
4. **Розподіл IC**: `P := min(f32(повзунок production · IC), ліміт ресурсів)` (economy.md §3.2); для кожного
   незавершеного елемента в порядку черги з IC на добу > 0:
   * чекає людських ресурсів → прогрес з `frac = 0`;
   * інакше `frac := min(1, P / IC_на_добу)`, `used := f32(frac · IC_на_добу)`; якщо ресурсів вистачає на `used` —
     спожити (1 : 2 : 0.5), `P −= used`, прогрес з `frac`; інакше — прогрес з 0.
   Елементи з IC на добу ≤ 0 не отримують нічого. Залишок `P` пропадає.
5. **Пост-цикл**: дата для інтерфейсу; ШІ з `new_model` піднімає моделі дивізії й бригад до найновіших; будівлі в
   провінціях, які країна більше не контролює, скасовуються; кожна одиниця з прогресом ≥ 1 завершується (§3.3).

### 3.2 Прогрес за добу (`0x4F1010(frac)`)
```
частка := frac
накопичувач := f32(накопичувач + 1.2·frac)
прогрес := f32(прогрес + frac / (дні · (1 − gearing)))      // одне округлення при записі
прогрес ≤ 1;  накопичувач ≤ 3                                // порівнюються неокруглені значення
якщо накопичувач > 0.999: накопичувач := max(0, накопичувач − 1)      // доба зарахована
інакше: людина втрачає gearing (:= 0)
```
За повного фінансування накопичувач росте на 0.2 на добу до 3, тож людина витримує ≈ 2 доби без фінансування.
ШІ gearing не втрачає. Очікування людських ресурсів (frac = 0) теж спустошує накопичувач.

### 3.3 Завершення одиниці (`0x4F2620`)
`прогрес := max(0, прогрес − 1)`; наступна одиниця чекає людських ресурсів; gearing `+= economy[9]`, але не більше
`GEARING_BONUS − economy[8]` (для фабрик IC — без приросту).
* **Дивізія або бригада** → новий юніт іде в **пул нерозгорнутих** (`C+0x451C`), а не на карту: міцність — до
  стелі типу, досвід `max(0, (MODIFIER_MP_EXPERIENCE − 1)·100)`; `done += 1`. Коли серія готова — елемент
  видаляється (ШІ перераховує повзунки, economy.md §7.4). Інакше з `upgrade` моделі піднімаються до найновіших, а
  gearing зменшується на `рівні_дивізії·economy[80] + Σ рівні_бригад·economy[81]` (ваніль 0). Модернізація може
  змінити тип за посиланням моделі.
* **Конвой** → `size` таблиці (ваніль 10) у пул транспортів (`C+0x3A10`) або ескортів (`C+0x3A14`).
* **Будівля без провінції** → лічильник готових нерозміщених; **з провінцією** → розміщення наступного дня (§3.1):
  максимальний рівень слоту провінції зростає на `size` будівлі, не вище ліміту виду (`0x4D0BF0`: 100 для IC, 1.0
  для інфраструктури, 10 для решти); без місця елемент стає «без провінції».

## 4. Додавання й скасування ✅

### 4.1 Замовлення (команда, обробник `0x477EF0`)
Відправник (планувальник ШІ або інтерфейс) сам рахує IC на добу, дні й людські ресурси і передає їх у команді.
ШІ замовляє дні всієї серії, IC лише за дивізію й не замовляє, якщо людських ресурсів не вистачає. Обробник:
* дні однієї одиниці — за §2.2;
* будівлі IC, берегових і сухопутних фортів та інфраструктури з провінцією: дні й передані дні множаться на
  `1/clamp(10·інфраструктура, 1, 10) + 0.9` (100 % → 1.0, 10 % → 1.9); перший же щогодинний перерахунок цей штраф
  прибирає — і в людини з `unitcost`, і в ШІ;
* будівля того ж виду в тій самій провінції вже в черзі → серія подовжується, якщо сумарний `size` вміщується в
  ліміт; інакше замовлення відкидається;
* від'ємні передані дні — замовлення частково виконаного (лише дивізії й бригади мають залишок серії);
* від'ємний IC → IC за модулем, `unitcost = 0`, а для ШІ — на початок черги;
* людські ресурси першої одиниці **знімаються одразу** (якщо не вистачає — елемент чекає); кожної наступної —
  після завершення попередньої.

### 4.2 Сценарій (`division_development`, `brigade_development`, `province_development`, `convoy_development`)
Елементи йдуть у кінець черги в порядку файлу. Після блоку (не для збереженої гри):
```
дні := §2.2 для однієї одиниці
R   := 360·Δрік + 30·Δмісяць + Δдень між date і стартом сценарію     // 30-денні місяці
якщо R < дні: прогрес := f32(1 − R/дні)
якщо manpower = 0: manpower := §2.4 + бригади 1..4
якщо cost ≤ 0: cost := §2.3 (з попередженням);  інакше cost із файлу
якщо прогрес > 1.5: прогрес := прогрес / дні                          // задано в днях
```
Людські ресурси при завантаженні не списуються.

### 4.3 Скасування (`0x47B750`)
Якщо людські ресурси поточної одиниці вже списано — вони повертаються; витрачений IC — ні. Будівля з готовими
нерозміщеними одиницями лишається в черзі (серія урізається до готових).

## 6. Модернізація 🔎
Повзунок модернізації й потреба модернізації з чергою не пов'язані (виробництво бере лише повзунок production).

## 7. Німеччина 1936 — перша доба ✅
Три елементи сценарію (порядок файлу):

| елемент | модель: cost / buildtime / manpower | `cost` у файлі | `date` | дні | прогрес на старті | після доби 1 |
|---|---|---|---|---|---|---|
| Admiral Graf Spee (важкий крейсер) | 7 / 310 / 1 | 5.6 | 1936-01-06 | 310 | 0.98064518 | 0.98387098 |
| 8. Zerstörergeschwader (есмінці) | 2 / 120 / 0.5 | 1.6 | 1936-03-01 | 120 | 0.49166667 | 0.50000000 |
| 4. Unterseebootsflottille (підводні човни) | 2 / 110 / 0.5 | 1.6 | 1936-03-01 | 110 | 0.44545454 | 0.45454544 |

* Модифікатори: міністри для цих типів 1.0; PRODUCTION_TIME = PRODUCTION_COST = 1.0; GEARING_BONUS 0.96;
  технологічних дельт немає.
* Доба 1: `P = f32(0.2·135) = 27`; усі три повністю профінансовані, використано 8.8 IC (metal −8.8, energy −17.6,
  rare −4.4), 18.2 IC пропадає; накопичувач f32(1.2) − 1 = 0.20000005.
* Гра стартує о 00:00, тож до першої доби відбувається 23 щогодинні перерахунки: **ШІ** лишає 5.6 / 1.6 / 1.6 =
  8.8 IC (нові значення не менші), **людина** платить 7 / 2 / 2 = **11 IC уже в першу добу**. Прогрес і
  завершення однакові, бо все повністю профінансовано.
* Graf Spee готовий на **6-й** добі (збігається з `date`) → у пул нерозгорнутих.
* Есмінці й підводні човни: після 61 доби прогрес f32 0.99999952 / 0.99999946 < 1 → готові на **62-й** добі, на день
  пізніше за `date` сценарію.

## 8. Реалізація в `dh-sim`
`dh-data::production` читає елементи черги сценарію й таблиці будівель і конвоїв; `dh-sim::production` рахує
дні, IC і людські ресурси (§2), щогодинний перерахунок і споживання припасів (§2.5), добу черги (§3.1–§3.3) — у
системі `Economy` після CG — і пул нерозгорнутих (`Country::undeployed`). Повзунок production ШІ — `min(потреба
черги/IC, 1 − CG − reinforcement)`. Тести на реальних даних відтворюють усі числа §7 точно. Спрощення: усі країни —
ШІ (правила людини §2.2, §2.3, §3.2 не застосовуються); технологічні дельти моделей — 0; доступність моделей не
перевіряється (щоденне підтягування моделей і `upgrade` не діють); стеля міцності — 100; розгортання пулу немає;
будівлі записуються окремо (`World::buildings_built`), а не в провінції; придатна провінція — будь-яка
контрольована; штраф інфраструктури при замовленні не застосовується (його й так прибирає перерахунок); немає
планувальника виробництва ШІ й перестановки черги.

## 9. Відкриті питання
1. Година старту після завантаження сценарію прийнята 0 (конструктор дати обнуляє годину, у `startdate` її немає);
   код, що копіює дату старту в годинник, не знайдено.
2. Чи дата «зараз» під час розбору сценарних елементів уже дорівнює даті старту.
3. Поле `speed`.
4. Розгортання юнітів із пулу на карту.
5. Ріст поточного рівня будівлі до максимального (`economy[53]`), умова придатності провінції (`0x49FA30`).
6. Що саме передає діалог замовлення в інтерфейсі; перестановка черги; повзунок модернізації.
7. Режим округлення FPU прийнято типовим (до найближчого); локальні перемикання не перевірено.

## 10. Незалежна перевірка: поправки ✅
1. **Перерахунок днів і IC — щогодини** (повідомлення години, цикл перед перевіркою «година = 0»), а не лише о
   00:00. Тому людина платить 11 IC за Німеччину вже в першу добу, ШІ — 8.8.
2. **Штраф інфраструктури губить і ШІ**: множник 1.0..1.9 лише збільшує дні, тож правило «ШІ бере лише менше»
   повертає дні без штрафу; штраф впливає щонайбільше на одну добу, а тримається лише в людини з `unitcost = 0`.
3. Елементи, що чекають людських ресурсів, отримують прогрес із `frac = 0` (накопичувач спустошується — людина може
   втратити gearing під час очікування); елементи з IC ≤ 0 не отримують виклику взагалі.
4. Непридатна провінція будівлі людини — одиниця губиться мовчки.
5. Стеля міцності типу (`C+0x40A2`) — задається блоком сценарію країни (ніж «хто пише — невідомо»).
6. Ліміт рівня будівлі за видом: 10 для видів 2..10, 1.0 для інфраструктури, 100 для IC.
7. Розміщення завершених будівель іде навіть без правила `production`; команди виробництва надсилаються лише коли
   гра їх приймає (`0x42E980`).
8. Підтверджено: §2.2 (округлення застосовується до f32-суми; порівняння з бригадою — лише слот 0), §2.3, §2.4,
   дельти технологій від моделі 0, правила перерахунку людини й ШІ, §3.2 точно, §3.3, §4.1–§4.3, §5 і всі числа §7.
