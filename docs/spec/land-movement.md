# Специфікація: рух сухопутних юнітів (час переходу, пошук шляху, прибуття)

Область: як Darkest Hour 1.05.1 (GOG) рахує, скільки годин сухопутний стек (армія/корпус — об'єкт
юніта з кількома дивізіями) іде з провінції A у сусідню провінцію B; як будується сухопутний маршрут;
коли рух у ворожу провінцію перетворюється на атаку.

Джерело фактів — `Darkest Hour.exe` (32-бітний PE, база образу `0x400000`), розібраний за адресами (VA),
та файли гри (`db\misc.txt`, `db\units\modifiers.csv`, `map\terrain types.csv`, `db\Province.csv`,
`db\difficulty.csv`, сценарій 1936). Код гри **не** копіюється: нижче — опис поведінки власними словами;
адреси, зміщення і константи наведено точно, щоб кожен міг перевірити.

Позначки:

* ✅ — підтверджено на даних гри (обчислення, звірка з файлами);
* 🔎 — прочитано з коду `Darkest Hour.exe` (VA поруч);
* ❓ — гіпотеза / не перевірено до кінця.

Пов'язані документи: [map-adjacency.md](map-adjacency.md) (типи з'єднань, перевірка ребра `0x4318D0`),

## 0. Коротко

Час одного кроку A→B (години, ціле) для сухопутного стека, що йде суходолом:

```text
км      = Відстань(A, B) · 100                                  // 0x44A980, одиниця 100 км
км_еф   = км · (2.4 − інфра(B)) · річка/протока · (1.25, якщо B під контролем ворога) · місія · пальне
v       = ШвидкістьСтека(B)                                     // 0x507FF0, км/год
години  = max(1, trunc(км_еф / v))                              // 0x430E30
```

`ШвидкістьСтека(B)` = мінімум по дивізіях від `maxspeed / рух[рельєф B] · (1 + mod_рельєф) · (1 + mod_погода)`,
далі множники постачання (ESE або 0.1), ORG, бою, країни, складності; нижня межа 1.0; потім **× 0.75**;
потім бонус рис генерала. Деталі — §3–§4.

Маршрут — A* (`0x431220`) із сухопутною таблицею методів `0x7E8694`: вартість кроку — **безрозмірна**
(рельєф × інфраструктура + надбавки), не кілометри й не години; евристика ≈ 0 (§6).

Атака: щогодини, якщо наступна провінція маршруту містить сухопутні війська країни, з якою стек у війні,
стек ініціює бій за цю провінцію (`0x5AFA70`) (§8).

### 1.4 Відносини країн 🔎

У країни `+0x12DA` — таблиця записів «я ↔ інша країна» по 44 (`0x2C`) байти на ID іншої країни. Байтові
прапорці всередині запису: `+0x2C`, `+0x31`, `+0x32`, `+0x37` (точні назви ❓).

* `0x44B240(C, O)` — **«C у війні з O»**: хибно, якщо O не існує або O == C; істинно, якщо будь-яка з них —
  спеціальна країна з ID `0x157` (343) ❓ (повстанці); хибно, якщо перевірка `0x585EC0` (поле запису `+0xC`) ❓;
  інакше — байт `+0x2C`. Інтерпретація «війна» узгоджується з усіма місцями використання (вороги в
  провінції, блокування `through`, штраф вартості шляху) ❓.
* `0x44A650(C, O)` — **«дружня для O»**: O == C; не у війні (`+0x2C` = 0) і (`+0x32` або сюзерен/васал
  (`+0x3B30` таблиці відносин) або `+0x31`).
* `0x585E80(C, O)` — байт `+0x37`: **військовий доступ** C на територію O ✅ (land-combat.md §4.3; ставиться з
  `access = yes` секції відносин сценарію, сетер `0x5893B0`), а не союз. Напрям ✅: метод викликається на таблиці
  C з ID O, а завантажувач таблиці (`0x586340`, запис — `0x588750`) кладе `relation = { tag = O access = yes }`
  з блоку країни C саме в запис C про O. Тобто ключ у блоці C дає доступ **військам C** на територію O (ваніль
  1936: ENG → BHU, IRQ, NEP, OMN, YEM; SOV → MON, TAN; USA → CUB, LIB, PHI; POR → SAF; JAP ↔ MAN; CHI, CSX, CXB —
  кожна до двох інших).
* Уточнення ✅ (land-combat.md §4.3): `+0x12DA` — **вказівник** на таблицю; запис для країни з ID i — `таблиця +
  0xC + 0x2C·i`, тож зміщення вище відлічено від початку таблиці: `+0x2C` = байт запису `+0x20` (війна), `+0x31` =
  `+0x25`, `+0x32` = `+0x26` (🔎 союзник по війні), `+0x37` = `+0x2B` (доступ).
* Прапорець «людина/AI» країни — `0xDC0F94[ID]` (≠ 0 — гравець): саме за ним `0x76B8B0` обирає таблицю
  `HUMAN` чи `AI` з `difficulty.csv` (§3.4). 🔎

## 3. Швидкість стека в провінції B (`0x507FF0`, vtable `+0x78`) 🔎

Аргумент — провінція **призначення** B. Результат — `f32`, км/год.

### 3.1 Алгоритм

```text
якщо кількість дивізій < 1: повернути 1.0

ніч_год := значення з combat[199..201] за кліматом B (+0x250), місяцем і півкулею (§3.3)
є_ніч   := ніч_год > 0
частка_ночі := ніч_год / 24 ; частка_дня := 1 − частка_ночі     // див. §3.3 щодо того, що саме множиться

підміна_пального := DefaultSpeedFuel ≥ 0
best := 200.0
половина := ні
для кожної дивізії d:
    v := d.maxspeed()                                  // 0x500700
    якщо підміна_пального і d.без_пального і d.out_of_fuel_speed < v:  v := d.out_of_fuel_speed
    x := v / рух[рельєф B]                              // double з terrain types.csv, (f32)
    якщо рельєф B ∈ 0..7: x := x · (1 + d.mod[MOV_<рельєф>])   (f32)
    якщо погода B ∈ 0..6: x := x · (1 + d.mod[MOV_<погода>])
    якщо є_ніч:           x := x · ((1 + d.mod[MOV_NIGHT]) · частка_ночі + частка_дня)
    якщо x < best: best := x                            (f32)
    якщо стек не відступає і d.ORG < 1.0: половина := так
якщо половина: best := best / combat[209]               // 2.0
якщо стек не відступає:
    s := min(ESE стека, 1.0)                            // 0x51C2F0
    best := best · (s, якщо в постачанні (0x523D80), інакше combat[208] = 0.1)
якщо стек у бою (+0x11C):              best := best · combat[206]
якщо під бомбардуванням (+0x176):      best := best · combat[207]
best := best · країна_команди.+0x13C2C                    // §3.4
x := best · (1 + модиф_складності(MOVE_SPEED))           // §3.4
якщо x < 1.0: x := 1.0
best := x · 0.75                                          // 0x7E4094
якщо є генерал і кількість дивізій ≤ ліміт його звання (0x50A330): бонуси рис (§3.5)
повернути best
```

* Отже, стек рухається зі швидкістю **найповільнішої** дивізії в умовах провінції B, а мінімальна
  можлива швидкість (без рис генерала) — `1.0 · 0.75 = 0.75` км/год.
* `рух[t]` — таблиця 11 `double` за `0xAD29C8` з `terrain types.csv` (map-index-grids.md §4). У цій функції
  значення ≤ 1e-5 **не** замінюється на 1.0 (на відміну від `0x4315F0`) — для рельєфу 10 (`Terra incognito`,
  0) було б ділення на нуль ❓ (на звичайній карті такого рельєфу в провінцій немає).
* ESE береться з першої дивізії (`0x51C2F0` → `0x4FD120(1)`); її розрахунок і умова «в постачанні»
  (`0x523D80`; для країни `0x157` завжди «так») — тема окремої специфікації постачання (❓).

### 3.2 Модифікатори рельєфу й погоди 🔎✅

## 4. Час одного переходу A→B (`0x430E30`) 🔎

Аргументи: стек, A, B, запис суміжності A→B (тип з'єднання `+4`). Результат — ціле число годин ≥ 1.
Нижче — сухопутна гілка (флотську частину не описано).

```text
// 1) Спрощення лише для стеків AI (0xDC0F94[країна] = 0):
якщо B — Ocean (8): повернути 1
якщо A — Ocean і B — суходіл і контролер B дружній (0x44A650): повернути 1

// 2) Базова відстань
d := Відстань(A, B) · 100                       // 0x44A980, (f32), км
якщо B — суходіл:
    d := d · (2.4 − infra(B))                   // 0x7E4084, infra з 0x4ECC50, (f32)
    тип 1 (river):        d := d · 1.25         // 0x7E4080
    тип 2/3 (sea/canal):  d := d · 1.33         // 0x7E407C
якщо d < 1: d := 1

// 3) Посадка/висадка (рівно одна з A, B — вода 8/9)
v := 4.0
якщо (A вода) ≠ (B вода):
    d := 100 км; якщо в A (або, якщо в A немає, — в B) є порт (+0x46A ≠ 0) з дружнім контролером: d := 50
    якщо контролер B у війні з нами: d := 2·d · (1 + 0.1 · кількість_дивізій)
    // швидкість лишається 4.0 км/год, §3 не викликається
інакше:
    v := ШвидкістьСтека(B)                      // §3

// 4) Вхід у ворожу провінцію (обидві — суходіл)
якщо контролер B у війні з нами (0x44B240): d := d · 1.25

// 5) Місія (якщо стек не відступає — лише для 5/6; для 1/4/33 — завжди)
місія 6 reserves,        контролер B є і не ворог:  d := d · mission[19] / ефективність[6]
місія 5 support_defense, контролер B є і не ворог:  d := d · mission[16] / ефективність[5]
місія 1 attack:          d := d · mission[3]  / ефективність[1]
місія 4 support_attack:  d := d · mission[13] / ефективність[4]
місія 33 ❓:             d := d · mission[90] / ефективність[33]
// ефективність[m] — f32 країни за зміщенням +0xE360 + 4·m (❓ поточна ефективність місії)

// 6) Без пального: будь-яка дивізія без пального і стек не відступає → d := d · combat[210] (3.0)
//    (для флоту — лише для гравця)

години := trunc(d / v)                          // _ftol 0x7A5BEC, відкидання дробу
якщо години < 1: години := 1
```

Зауваги:

* Інфраструктура, рельєф, погода — усе береться з провінції **призначення** B. Інфраструктура A не важить.
* `2.4 − infra` дає ×1.4 при 100 % і ×2.4 при 0 %. ✅ (константа `0x7E4084` = 2.4000001f)
* Тип з'єднання береться з **регулярної** частини списку A (map-adjacency.md): `river` 1 → ×1.25,
  `sea`/`canal` → ×1.33. Тип 4 (`impassable`) сюди не доходить (§4.1).
* Штрафи місій support_defense/reserves (0.5) **зменшують** час удвічі — це прискорення резервів.
* Для бітової точності: значення `d` зберігається як `f32` після кожного множення; `v` — `f32`; ділення й
  відкидання — у x87.

### 4.1 Обгортка «час між двома провінціями» (`0x430CC0`) 🔎

Метод об'єкта пошуку шляху (this = pathfinder), аргументи: стек, A, B.

* Для сухопутного стека шукається B серед **регулярних** сусідів A; якщо знайдено і тип ≠ 4 —
  повертається `0x430E30(стек, A, B, запис)`.
* Інакше (не сусіди або тип 4) — A* (`0x431220`) від A до B цим pathfinder'ом; якщо шлях знайдено —
  сума `0x430CC0` по сусідніх парах шляху (кожен доданок ≥ 1); якщо ні — **1**.

### 4.2 Час до кінця маршруту (`0x51BE90`) 🔎

Якщо маршрут порожній — «зараз». Інакше: дата прибуття в наступну провінцію (`+0x222`) плюс сума
`0x430CC0` для пар `маршрут[i] → маршрут[i+1]` (сухопутний стек — pathfinder `0x7E8694`). Використовується
для відображення/синхронізації ❓.

## 5. Накопичення прогресу і збережені поля

### 5.1 Дата 🔎

6 байт: `+0` година (u8), `+1` день (u8), `+2` місяць (u8), `+3` — не використовується, `+4` рік (i16).
Арифметика дат (`0x42DB80` — додати години, `0x42E060` — різниця, `0x42DD70`/`0x42DDD0` — порівняння)
переводить дату в години як `година + 24·(день + 30·(місяць + 12·рік))`, тобто **місяць = 30 днів,
рік = 360 днів** (`0x21C0` = 8640 год). ❓ Чи день/місяць 0-базові.

### 5.2 Модель руху: дві дати, а не лічильник ✅🔎

Прогрес не накопичується «по кілометрах»: стек зберігає дату виходу (`+0x228`) і дату прибуття (`+0x222`) у
наступну провінцію маршруту (`+0x22E`). Прибуття відбувається, коли поточна дата досягає дати прибуття ❓
(код самого переходу в нову провінцію не розібрано, див. §10). Частка пройденого = `(зараз − вихід) /
(прибуття − вихід)`.

Збережені поля стека (scenario.md): `movetime` — дата прибуття (❓ саме `+0x222`; записувач `0x564550`
бере дату за зміщенням `+0x204` об'єкта, базу не встановлено), `movement` — список ID провінцій маршруту
(код ключа `0x1A0`; `movetime` — `0x24F`; 🔎 `0x565572`, `0x565608`), `prevprov` — попередня провінція.

### 5.3 Перерахунок під час руху (`combat[202]`) 🔎

Якщо ввімкнено (`0xDC16F4`), у стека стоїть `+0x253`, він не в бою й не під бомбардуванням, а прибуття ще
не настало (`0x51DB7E..0x51DE04`):

```text
T_старий := прибуття − вихід            // години
T_новий  := 0x430CC0(pathfinder 0x7E8694, стек, location, маршрут[0])
якщо T_новий ≠ T_старий:
    лишилося := прибуття − зараз
    лишилося' := round(лишилося / T_старий · T_новий)   // fistp, округлення до найближчого
    пройдено' := T_новий − лишилося'
    якщо пройдено' > 0: вихід := зараз − пройдено' ; прибуття := зараз + лишилося'
```

Тобто зберігається **частка** пройденого шляху. У ванілі `combat[202] = 0` — час кроку фіксується в
момент його початку.

## 6. Пошук сухопутного шляху 🔎

### 6.1 Ядро

Загальний A* `0x431220` (див. map-distances.md §7.2): двійкова купа `0x893720`; на кожному кроці
`g' = g(поточний) + вартість(стек, поточний, сусід, запис)`; сусід оновлюється, якщо ще не відвіданий
(`f ≤ 1e-4`) або `g'` **строго** менше; `f = g' + евристика(стек, сусід, ціль)`.

### 6.2 Таблиці методів (усі успадковують `0x7E518C` → `0x7E8BE0`)

| vtable | Хто використовує | старт `+0x34` | крок `+0x30` | вартість `+0x3C` | евристика `+0x40` |
|---|---|---|---|---|---|
| `0x7E8BE0` | базовий «сухопутний» | `0x4318A0` | `0x4318D0` | `0x4315F0` | `0x4316E0` |
| **`0x7E8694`** | накази руху сухопутного стека (UI `0x5BBDA1`, `0x508F70`, `0x51BE90`, `0x51DC62`) | `0x431BB0` | `0x431C10` | `0x431C80` | `0x4316E0` |
| `0x7E8B90` | те саме для флоту | `0x4321A0` | `0x4321E0` | `0x432290` | `0x4316E0` |
| `0x7E8B48` | те саме для авіації | `0x431F40` | `0x431F90` | `0x432020` | `0x4320B0` |

Вибір у UI (`0x5BB14F`): авіація (`+0x30`) → `0x7E8B48`; суходіл (`+0x28`) → `0x7E8694`; інакше —
`0x7E8B90`. Старт — кінець поточного маршруту (`0x51BE60`) або поточна провінція. 🔎

### 6.3 Сухопутний наказ (`0x7E8694`)

* **Старт** `0x431BB0`: ціль не заблокована (`+0x180`), ID старту й цілі різні й ненульові; якщо ціль — морська
  провінція, що межує з суходолом (`+0x471`), — дозволено; якщо ціль — вода — ні; інакше `CanEnter(стек, ціль)`
  (`0x521440`, §7.2).
* **Крок** `0x431C10`: перевірка ребра `0x4318D0` (не назад до батька; сусід ≠ 0 і не заблокований; для
  сухопутного стека тип 4 заборонено; `through` типів 1/2 блокують ворожі флоти, типу 3 — ворожий контролер
  чи війська — див. map-adjacency.md §6.1–6.2); сусід == ціль → дозволено; сусід — вода → ні; інакше
  `CanEnter(стек, сусід)`.
* **Вартість** `0x431C80` (сусід = провінція, у яку входимо):

```text
c := рух[рельєф] · (1 + 2.5 · (1 − infra))           // 0x7E409C = 2.5, (f32)
якщо c ≤ 1e-5: c := 1.0
тип 1 (river): c += 0.1 ; тип 2/3: c += 0.75
якщо у сусіда є контролер, стек сухопутний і контролер у війні з нами:
    c += 0.1
    якщо +0x46E сусіда і в сусіді є ворожі сухопутні війська (0x507F50): c += 10.0
```

* **Евристика** `0x4316E0`: `Відстань(вузол, ціль) · 0.012` (суходіл) або `· 0.002` (вода), одиниця 100 км.
* **Ціль** `0x431880`: ID поточного == ID цілі.

Наслідки:

* Вартість **не залежить від відстані** і від швидкості — маршрут мінімізує суму «складності» провінцій
  (≥ 1.0 за крок на суходолі; при 100 % інфраструктури = коефіцієнт рельєфу, при 0 % — ×3.5).
  Евристика (≈ 0.012 на 100 км) завжди значно менша за вартість кроку — пошук фактично Дейкстра за цією
  вагою.
* Річка в пошуку коштує +0.1, а в часі руху ×1.25 — це різні моделі. ✅ (коди)
* Порівняння з морським A* (map-distances.md §7.2): там вартість = `відстань × (рух[рельєф] + 0.5/0.75)`,
  тобто в кілометрах; у сухопутному — без кілометрів, з інфраструктурою.
* Базова вартість `0x4315F0` (vtable `0x7E8BE0`): те саме, але **без** інфраструктури і з +0.5 за річку.

## 8. Прибуття у ворожу провінцію: тригер атаки 🔎

Щогодинна обробка стека `0x51D510` (за умови `0x42E980` — повертає 1, якщо об'єкт `0xBD14C0` відсутній або
не активний; ❓ мережева гра): якщо стек сухопутний,
**не відступає** і маршрут не порожній (`0x51EFAA..0x51F05A`):

1. N := перша провінція маршруту (`0x526810`).
2. Якщо в N є хоч один сухопутний невідступаючий юніт країни, з якою стек у війні (`0x507F50`), і
3. стек ще не бере участі в бою за N (`0x507F20`: серед боїв `+0x120` немає бою з провінцією-ціллю N),
4. то викликається `0x5AFA70(менеджер боїв [0xD61566], стек, N)` — стек атакує N.

Тобто атака починається, щойно стек має **наступним кроком** провінцію з ворожими військами, — не після
прибуття. Порожня ворожа провінція не дає бою: стек іде з часом ×1.25 (§4, крок 4); що відбувається з
контролем провінції після прибуття — ❓ (§10). Вплив бою на рух: швидкість у бою множиться на
`combat[206]` (1.0) (§3).

## 11. Відкриті питання

1. **Сам момент прибуття**: де стек змінює `location`, знімає вузол маршруту, ставить нові дати й змінює
   контролера порожньої ворожої провінції (не знайдено; кандидати — інші частини `0x51D510`, `0x51CB40`).
2. Яке саме поле стека записується як `movetime` (`+0x222`?) і чи `movetime` — прибуття в наступну
   провінцію чи в кінцеву (§5.2).
3. ESE (`0x4FD120`) і умова «в постачанні» (`0x523D80`) — потрібна специфікація постачання.
4. Ділення `modifiers.csv` на 100: місце в коді не знайдено (§3.2).
5. Відповідність ефекту міністра `unit/speed` → поле `+0x13C2C` (§3.4) і чи є інші джерела (технології,
   політики).
6. Назви байтів відносин `+0x2C/+0x31/+0x32/+0x37`, перевірка `0x585EC0`, прапорець стека `+0x17C`, країна
   `0x157` (§1.4, §7.2).
7. Прапорці стека/провінції `+0x253`, `+0x176`, `+0x46A`, `+0x46E`; дивізії `+0x155`.
8. Ефективність місій `країна + 0xE360 + 4·m` (джерело, `db\mission_eff.csv`?), місія 33.
9. Таблиця місяців/зон для ночі (§3.3) — у ванілі вимкнено.
10. Синхронізація прибуття (`combat[203..205]`), стратегічне перекидання (`mission[7..10]`), десант
    (`mission[72..73]`), рух на транспорті — не розбиралися.
11. Перевірка на живій грі: порівняти години з таблиці §9 з інтерфейсом гри (зараз — лише обчислення за
    кодом).
