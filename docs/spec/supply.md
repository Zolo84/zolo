# Постачання (supply) — специфікація

Статус: чернетка (обмежений бюджет). Позначки: ✅ перевірено в коді, 🔎 виведено/ймовірно, ❓ невідомо.
Нумерація `economy[n]`/`combat[n]` — позиції в `misc.txt`, як у land-movement.md.

| країна | `+0x3968` | транспортна ємність (TC), ціле | ✅ запис `0x49ADCA` |

## 1. Тест «стек у постачанні» (`0x523D80`, this = стек) ✅ (структура), 🔎 (смисл полів)

Повертає `true`, щойно спрацює будь-який пункт (по порядку):

1. ID країни-власника (`стек+0x248 → +6`) == `0x157` → завжди в постачанні ✅ (❓ яка це країна; 0x157 = 343).
2. Якщо віртуальний предикат стека `vt+0x28` (🔎 «сухопутний стек») і в об'єкта `vt+0x10()` ненульове поле `+0x2AE`
   або `+0x2B2` → `true` ❓ (ймовірно, спец-стан/спец-тип).
3. Якщо `vt+0x30` і в об'єкта `vt+0x18()` ненульове `+0x2A6` → `true` ❓.
4. Провінція перевірки P: `стек+0xC` (поточна); для стеків, де `vt+0x2C` або `vt+0x30` істинні (🔎 повітряні/морські) —
   `стек+0x212` (база).
5. `власник != 0` і `0x49ECE0(власник, P)` (= `0x4E9FB0(P, власник)`, див. нижче) → `true`.
6. Країна командування `C2 = таблиця[стек+0x146]` (`0x89CA98`); якщо вона існує й ≠ власник і `0x4E9FB0(P, C2)` → `true`.
7. Якщо стек **у бою** (`+0x11C` кількість ≠ 0): для кожного «звичайного» сусіда N провінції P (`+0x290`/`+0x298`):
   * контролер N == власник: `true`, якщо (N`+0x482` == компонента столиці власника **і** власник`+0x39C4` > 0)
     або (N`+0x482` ≠ 0 і провінція-база компоненти `+0x270` > 0). Увага: у першій умові береться
     `+0x39C4` **власника** провінції N (`+0x3D4`) — 🔎 на практиці той самий.
   * контролер N ≠ власник: відношення контролер→власник (`контролер+0x12DA`, `0x585F10`, 🔎 союз/військовий доступ)
     істинне, N`+0x482` == компонента столиці контролера і контролер`+0x39C4` > 0 → `true`.
8. Інакше `false`.

### 1.1. `0x4E9FB0(P, C)` — «провінція P постачається країною C» ✅ (структура)

* P`+0x12` == 0 → `false`.
* S := `0x4E9D30(P, C)` — ID провінції-джерела постачання для C (🔎). Якщо S ≤ 0 → `false`.
* `true`, якщо будь-що:
  1. S`+0x270` > 0 (провінційний запас);
  2. власник S існує, його фактична столиця (`0x44E170`) == ID(S) і власник S `+0x39C4` > 0;
  3. S`+0x482` == компонента столиці C (`0x44E190`: `провінція[столиця]+0x482`) і C`+0x39C4` > 0;
  4. власник P існує, його фактична столиця == ID(S) і власник P `+0x39C4` > 0.

### 1.2. `0x4E9D30(P, C)` — вибір джерела 🔎

* Потрібні: P має контролера, P`+0x482` ≠ 0, у компоненти є об'єкт `[vt0]()+0x6C` (🔎 «континент/суходіл»),
  компонента столиці C ≠ 0; інакше 0.
* Якщо P`+0x482+0x4C` == 0 і (🔎) C має доступ до континенту P (`0x4CCCF2`), і континент компоненти столиці C ==
  континент P → повертає фактичну столицю C (`0x44E170`).
* Інакше перебирає список `континент+4` (🔎 бази/порти інших компонент, власник == C) — ❓ не розібрано.

Висновок для реалізації: «у постачанні» = провінцію можна зв'язати сухопутною компонентою зі столицею своєї
(або командувальної) країни, у якої є запас припасів > 0, або з провінцією, що має власний запас > 0 (заморські
бази, куди возять конвої). Обмеження відстані в цьому тесті **немає** ✅ — відстань впливає лише на ESE/споживання (❓).

## 2. ESE дивізії (`0x4FD120(with_stack)`, this = дивізія) ✅

```
ese := ESE_країни(C)                               // 0x44AAB0(0)
якщо 0x42DDD0(глоб.[0x8934F0]+0x14, дивізія+0x66) == false: ese += 0.25   // ❓ що за множина
якщо with_stack і стек != 0:
    якщо стек.кількість(+0xC) > 0 і рельєф провінції стека ∉ {8 Ocean, 9 River}:
        extra := (та сама перевірка множини == false) ? 0.25 : 0
        ese := (інфраструктура(провінції стека) + extra + ese) · 0.5
    якщо ese < 1.0 і стек.vt+0x28 і є командир 0x51C220
         і ранг/рівень командира 0x50A330 ≥ значення стек+0x22 (vt+4)       // ❓ семантика
         і командир+0x1E біт 0 («Logistics Wizard» 🔎):
        ese := min(ese + combat[161] (0.1), 1.0)
    якщо 0x51C8C0(стек) (🔎 «наступальне постачання») і дивізія+0x15F:
        ese := ese + C+0xE2F6
повернути ese
```

`ESE_країни (0x44AAB0)`: `min(1.0, TC / max(load, 0.001))`, де `TC = C+0x3968`, `load = C+0x396C` (обидва цілі) ✅.
Діапазон: без стека 0.001…1.0(+0.25); зі стеком ≈ 0…1.125, після бонусу наступу може перевищити 1 ✅.
У бою (land-combat §4 п.10) береться `(ESE − 1)·0.5`.

### 2.1. TC і навантаження (`0x49AD70`, країна) ✅/🔎

* `TC = round((C+0x3970 + max(10, IC·k)) · C+0x13C38 · C+0xE848)`; IC = `C+0x3924` (ціле), `k` = глобал `0xD7CA20`
  (🔎 `economy[1]` IC→TC 1.5); `+0x3970` — 🔎 додаткова TC; `+0x13C38`, `+0xE848` — 🔎 множники (`Transport Capacity modifier`).
* `load = round(Σ +0x3974 (дивізії: land·economy[19], air·economy[20], naval·economy[21] 🔎)
  + +0x3978 (окуповані провінції · economy[18], × 1/C+0xE84C) + +0x397C (нерозгорнуті · economy[17]·економіка[48]?)
  + +0x3980 (партизани · economy[22]) + +0x3984 (· economy[25] база в черзі) + +0x3988 (· economy[24]))`. Точні
  множення складових — ❓ (не розбирав).

## 3. Прапорці «немає припасів» (`+0x156`) і «немає пального» (`+0x157`) ✅

Обидва встановлює тільки функція споживання дивізії `0x5033C0(arg)` (this = дивізія; викликається з `0x51D2EA`,
`0x51E274`, `0x5D42E9`, `0x5DE147`). Частота: 🔎 **щогодини** — функція списання `0x44CCB0` ділить денну потребу
на 24 (множник `1/24`). Є дві гілки за глобальним байтом `0xDC16BC` (❓ опція/параметр), логіка прапорців у них
однакова.

1. Дивізія без стека (`+0x6C` == 0) — нічого не змінюється.
2. Країна дивізії `0x157` → обидва прапорці := 0, вихід.
3. Провінція списання L: провінція стека (`стек+0xC`); для сухопутної дивізії на транспорті — провінція/база
   об'єкта-перевізника (`vt+0x10()` → `+0x2AE`/`+0x2B2` → `+0x212`); для морської (`+0x161`) — `vt+0x14()+0x212`;
   для повітряної (`+0x160`) — `стек+0x212` (база) 🔎.
4. **Пальне**: `f = дивізія+0x10C · дивізія+0xF0 · 0.01` (🔎 базове споживання пального × сила у %).
   Якщо `f > 0`: потреба `0x4FD380(1, f, L, arg)` (модифікатори з `economy[65..66]` тощо, ❓), спроба списати
   `країна.0x44D190(потреба)`; невдача → `+0x157 := 1`, інакше `0`. Якщо `f ≤ 0` → `+0x157 := 0`.
5. **Припаси**: `s = дивізія+0x108 · дивізія+0xF0 · 0.01`; якщо `s > 0`: потреба `0x4FD570(1, L, arg)`
   (модифікатори `economy[63..64]` 🔎), спроба `країна.0x44CCB0(потреба, L)`; невдача → `+0x156 := 1`, інакше `0`.
   `s ≤ 0` → `+0x156 := 0`.

`0x44CCB0` (списання припасів, this = країна): потреба ≤ 0 або ID провінції 0 → успіх; для суходолу з компонентою
(`+0x482`) бере джерело `0x4E9D30(L, країна)` і списує з його провінційного запасу або із запасу країни (🔎);
неуспіх, коли запасу бракує. Тобто прапорці означають «цієї години не вдалося списати», а не «поза зоною постачання»
(це окремий тест §1).

## Відкриті питання

- ❓ Країна `0x157`: яка це (бунтівники?) — і в тесті, і в споживанні вона завжди «постачена».
- ❓ Предикати стека `vt+0x28/+0x2C/+0x30` і поля `+0x2A6/+0x2AE/+0x2B2` (транспорт/висадка).
- ❓ Повний алгоритм `0x4E9D30` (пошук джерела через інші компоненти/порти, список `континент+4`).
- ❓ Множина `[0x8934F0]+0x14` у ESE (+0.25) та поле дивізії `+0x66`.
- ❓ Умова «рангу» командира для Logistics Wizard (`0x50A330` vs `стек+0x22`).
- ❓ `0x51C8C0` — точна умова наступального постачання; запис `+0xE2F6` (`0x44615F`, `0x49084D..0x490880`).
- ❓ Точні формули `0x4FD380` / `0x4FD570` (вплив відстані, `economy[87]`, `country[10]`), гілка `0xDC16BC`.
- ❓ Складові навантаження TC (`0x49AD70`), `+0x3970`, `+0x13C38`, `+0xE848`, `+0xE84C`.
- Не досліджувалось: конвої, виробництво запасів, транспортна ємність у деталях, провінційні запаси (автоконвої,
  `economy[60]`), атриція поза постачанням (`combat[8..10]`).
