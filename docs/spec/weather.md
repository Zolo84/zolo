# Специфікація: погода (DH 1.05.1)

Позначки: ✅ простежено в коді, 🔎 імовірно, ❓ невідомо. Усі адреси — VA (image base 0x400000).

**Статус перевірки.** Усе, що позначено ✅, незалежно перевірено вдруге за дизасемблером (окремий прохід, §6):
сезонні предикати порівняно повним перебором (9 кліматів × 2 півкулі × 12 місяців, 0 розбіжностей), алгоритм
оновлення, фронти, `Dir`, `Seed`, ключові слова сценарію й споживачі збігаються; одне твердження спростовано й
виправлено нижче (бонус WinterSpecialist до швидкості теж вимагає ліміту командування, §4.1).

Реалізація: `dh-sim::weather` (оновлення, фронти), `dh-sim::attrition` (§4.3), рух (`dh-sim::march`,
`MoveConditions`) і бій (`dh-sim::combat`, рядок 12).

## 1. Коли оновлюється

* `WeatherUpdate(seed)` = `0x75DCC0` (cdecl). ✅
* **Кожні 6 ігрових годин**: обробник погодинного повідомлення 0x17 у `0x781D90` (`0x78211C`): якщо
  `година % 6 == 0` (00, 06, 12, 18) → `WeatherUpdate(msg.payload+0x12)` (`0x7821A9..0x7821C0`). ✅
  * `payload+0x12` = значення `rand()`, яке годинник узяв, створюючи повідомлення «час іде» (тип 0x131,
    `0x42CE48` → `[eax+0x12]` `0x42CEFE`); обробник 0x131 (`0x5AEA70..0x5AEB57`) для кожної години викликає
    `date.advance(1)` і шле 0x17 із тим самим `+0x12`. Тобто seed — випадкове 0..32767. ✅
* Ще один виклик — обробник повідомлення 0x4D (`0x7822D8…0x782674`, 🔎 «старт гри» — шле його ініціалізація
  `0x42EFB0` після `INIT_SCENARIO`): seed = `A + B + годинВідЕпохи(поточна дата)`, A/B — розміри двох
  списків об'єкта гри (`+0x272`, `+0x167DE`, vtable+4) ❓. Без перевірки години. ✅(виклик) 🔎(сенс)
* Після оновлення, якщо відкрито карту погоди (`[0xA98400] == 2`), перемальовується карта (`0x4DC8D0`). UI.
* Якщо `static` (`[0xD54671]`) ≠ 0 — функція виходить одразу: **ні клімат, ні фронти не змінюються** (`0x75DCCE`). ✅
  `static` ставить лише парсер `weather = { static = yes }` (`0x75CF66`); глобал ніде не скидається (🔎 «прилипає»
  між сценаріями однієї сесії).

## 2. Алгоритм `WeatherUpdate(seed)` ✅ (`0x75DCC0..0x75EAB1`)

```
if static: return
srand(seed)
m := місяць (0..11);  N := кількість провінцій [0x877650]
inPattern[i] := 0 для всіх i; enabled := #{i : prov[i].+0x180 == 0}
для кожного фронту P у глобальному списку [0xD5467C] (порядок списку):
    для кожного s у P.provinces: inPattern[s] := 1
```

### 2.1 Кліматичний крок (для **кожної** провінції i = 0..N-1, включно з морськими) ✅ `0x75DDE1..0x75E02B`

```
ev := ((seed + i) % 60 == 0)          // знакове idiv; «подія» 1/60, однакова для i ≡ −seed (mod 60)
p := prov[i]; w := p.weather
if deepWinter(m,p):                 FREEZE
elif onset(m,p) and ev:              FREEZE
elif thaw(m,p) and ev:               THAW
elif warm(m,p):                      WARM
(інакше без змін)
FREEZE: 0→1, 2→3, 4→5 (решта як була)
THAW:   3→2, 5→4, 2/4 без змін, інакше → (клімат==Muddy(4) ? 6 : 0)
WARM:   3→2, 5→4, 1→0, 6→(rand()%12==0 ? 0 : 6), інше без змін
POST (лише якщо inPattern[i]==0):
    2 або 4 → (клімат==4 and thaw(m,p)) ? 6 : 0
    3 або 5 → 1
```

Сезонні предикати (`m` 0=січ; N/S — півкуля провінції):

| Клімат | deepWinter `0x75DA20` | onset `0x75D7C0` | thaw `0x75D8B0` | warm `0x75DB30` |
|---|---|---|---|---|
| 1 Arctic | N: m≥9 або m≤3; S: 3..9 | N 8; S 2 | N 4; S 10 | N 5..8; S m≤2 або m≥11 |
| 2 Subarctic, 4 Muddy | N: m≥10 або m≤2; S: 5..8 | N 9; S 4 | N 3; S 9 | N 4..8; S m≤3 або m≥10 |
| 3 Temperate | N: **ніколи** (баг: `m≤1 && m≥11`, `0x75DAED..0x75DAFB`); S: 6 | N 10; S 5 | N 2; S 7 | N 3..9; S m≤4 або m≥8 |
| 0, 5, 6, 7, 8 | ні | ні | ні | **так** (завжди) |

Для фронтів (§2.2) ще два:

| Клімат | rainy `0x75DBD0` | dry (інлайн `0x75E0D3`, `0x75E703`, `0x75E8DB`, `0x75D6D8`; = `0x75DC70`) |
|---|---|---|
| 5 Mediterranean | N: m≥9 або m≤1; S: 4..7 | N: 5..8; S: m≥11 або m≤2 |
| 6 Subtropical | N: m=11 або m=0; S: 5..6 | ні |
| 7 Tropical | N: 4..10; S: m≥9 або m≤3 | ні |
| 8 Arid | ні | **завжди** |
| інші | ні | ні |

Наслідки: Temperate-північ узимку (гру…лют) кліматичний крок не чіпає — мерзлий ґрунт з'являється лише
подією в листопаді (1/60 за оновлення), тримається до березня (thaw+ev) або квітня (warm). Muddy-клімат у місяць
відлиги стає грязюкою; в «теплий» сезон грязюка сохне з імовірністю 1/12 за 6 год.

### 2.2 Фронти (patterns) ✅ `0x75E031..0x75E9C5`

Структура фронту (0x3C байт, ctor `0x75EF10`, vtable `0x7FA4C0`):
`+0x08` id {type,id}; `+0x16` список провінцій (vtable; `+0x1A` голова, `+0x1E` хвіст, `+0x22` кількість; вузол
`{value, prev, next}`); `+0x28` лічильник оновлень без руху (0); `+0x2C` speed (типово 3); `+0x32` centre (0 = нема);
`+0x36` heading 0..7 (типово 2 = east); `+0x3A` special (0).

```
lastR := seed                          // слот аргументу перезаписується кожним rand нижче
для кожного P у списку:
    r := rand(); lastR := r
    c := P.centre
    K := rainy(m, prov[c]) ? 20 : 10
    if P.provinces порожній: Seed(P, r)               // 0x75D660, див. нижче
    elif c != 0 and (r % K == 0 or dry(m, prov[c])):  // центр розсіюється
        prov[c].weather := isCold(prov[c]) ? 1 : 0
        P.provinces.remove(c); prov[c].+0x3E9 := 0; P.centre := 0
    moved := false; firstNew := 0
    для вузла s у P.provinces (по порядку; next запам'ятовується до обробки):
        if s == firstNew: break                       // щойно додані цього тіку не обробляються
        r2 := rand(); lastR := r2
        c := P.centre
        if c == 0:                                    // фронт без центру — розсіюється
            if r2 % (dry(m,s) ? 1 : 2) == 0: Clear(s); P.provinces.remove(s)
            continue                                  // без поширення
        d := Dist(s, c)                               // 0 = s==c; 1 = s сусід c; 2 = сусід сусіда; 3 = далі
        if d == 3:
            if r2 % (rainy(m,s) ? 12 : 6) == 0: Clear(s); P.provinces.remove(s)
        elif d == 2:
            if s.w ∉ {4,5} and (r2%100==0 or (s.clim==7 and r2%48==0)): s.w := isCold(s) ? 5 : 4
            elif s.w ∈ {4,5} and r2%48==0:                              s.w := isCold(s) ? 3 : 2
        elif d == 1:
            if not moved:
                h := P.heading; dir := Dir(c, s)
                if dir == h and P.counter >= P.speed:                Move(P, s)
                elif P.counter > P.speed+3 and dir ∈ {h, h+1, h-1} (mod 8): Move(P, s)
                elif P.counter > P.speed+6:
                    P.heading := (r2 парне) ? h+1 : h-1 (mod 8);   Move(P, s)
            if s.w ∉ {4,5} and (r2%73==0 or (s.clim==7 and r2%24==0)): s.w := isCold(s) ? 5 : 4
            elif s.w ∈ {4,5} and r2%100==0:                             s.w := isCold(s) ? 3 : 2
        Spread(P, s, r2)                              // для d = 0..3 (також якщо s щойно видалено при d==3)
    if not moved: P.counter += 1

Clear(s):  s.w := isCold(s) ? 1 : ((s.clim==4 and thaw(m,s)) ? 6 : 0)
Move(P,s): prov[P.centre].+0x3E9 := 0; prov[s].+0x3E9 := 1; P.centre := s; P.counter := 0; moved := true
Spread(P, s, r2):                                     // 0x75E688..0x75E8BA
    для кожного сусіда n (регулярний список s, по порядку):
        if isPrecip(n) or dry(m,n): continue
        F := rainy(m,n) ? 3 : 5
        X := max(1, Dist(n, P.centre) · F)            // Dist з ПОТОЧНИМ центром (міг щойно зсунутися)
        if r2 % X == 0:                               // ОДИН r2 на всіх сусідів s
            n.w := isCold(n) ? 3 : 2
            P.provinces.append(n); if firstNew == 0: firstNew := n
Dist(a, c): a==c → 0; c у списку сусідів a → 1; ∃ сусід b з a: c у списку сусідів b → 2; інакше 3   // 0x4E76F0
```

`isCold(s)` для щойно доданої провінції дивиться на її ґрунт (1 frozen ⇒ сніг), а для посилення/ослаблення —
на поточний опад (3/5 ⇒ хуртовина/сніг): дощ↔шторм, сніг↔хуртовина. ✅

**Напрям `Dir(c, s)`** (`0x75D220`): центри рамок провінцій `0x4D7620` (`x = x0 + (x1−x0)/2`, те саме y; рамка
`+0x3B2..+0x3BE`, піксельні координати карти, **y униз**). `dx = sx−cx`, `dy = sy−cy`, `r = dy/dx` (float):

| | r > 2 | 0 < r ≤ 2 | −2 ≤ r ≤ 0 | r < −2 |
|---|---|---|---|---|
| dx > 0 | 0 | 1 | 3 | 4 |
| dx < 0 | 4 | 5 | 7 | 0 |

`dx == 0`: `dy > 0` → 0, інакше → 4. Значення 2 (east) і 6 (west) **ніколи не повертаються**. Порівняно з картою
напрям дзеркальний по вертикалі: 0 «north» = провінція **нижче** на карті (на південь). ✅ (Ймовірно, баг осі y.)
Heading-токени парсера: north 0, northeast 1, east 2, southeast 3, south 4, southwest 5, west 6, northwest 7
(`0x75FBAD..0x75FC43`). Отже heading = east/west рухається лише через ±1-допуск або поворот.

**Новий фронт `Seed(P, r)`** (`0x75D660`): `i := r % (N−1) + 1` (обмеження [1, N−1]); шукати по колу (i+1, після N−1 → 1),
не більше 2N+1 спроб, першу провінцію з `!isPrecip`, рельєф ≠ 9, `+0x180 == 0`, `!dry(m,·)`. Якщо не знайдено —
нічого (фронт лишається порожнім). Інакше: `P.centre := i`, `+0x3E9 := 1`, `P.provinces.append(i)`,
`P.heading := r % 8`, `P.speed := r % 5 + 1` (1..5), `prov[i].w := isCold ? 3 : 2`. (Лічильник і `special` не скидаються.) ✅

### 2.3 Кількість «природних» фронтів ✅ `0x75E9CB..0x75EA91`

```
target := max(1, trunc(enabled / N · 24.0f))          // _ftol `0x7A5BEC` (усічення)
natural := #{P : P.special == 0}
if natural < target:  P := new Pattern(); список.append(P); Seed(P, lastR)   // не більше одного за оновлення
```
Фронти ніколи не видаляються: порожній фронт на наступному оновленні пересіюється в іншому місці (з тим самим
`special`). Повна карта ⇒ 24 природних фронти, набираються по одному за 6 год.

## 3. Сценарій, збереження, події

* `weather = { … }` у сценарії — парсер `0x75CE90` (виклик `0x78124C`): `static = yes|no` → `[0xD54671]`;
  кожен `pattern = { … }` → новий фронт (`0x75EF10`), розбір `0x75FAF0`, додається в кінець списку. ✅
  * Ключі фронту: `id = {type id}` (токен 0x523) → `+0x08`; `provinces = { … }` (0x1B7) → список; `centre` (0x3BD) →
    `+0x32`; `speed` (0x1AA) → `+0x2C`; `heading` (0x3BE, **ідентифікатор** north…northwest; інше — без змін) → `+0x36`;
    `special = yes` (0x19D) → `+0x3A` (у scenario.md відсутній). **Лапки:** лексер дає рядку в лапках тип 0x527 без
    пошуку ключових слів (`0x5344C9`), тому `heading = "northwest"` (як у ванільному `ardennes.eug`) **ігнорується** →
    heading лишається 2 (east); треба писати без лапок. ✅ Невідомий ключ — помилка «unknown lhs … (weather
    pattern)». Типові значення: speed 3, heading 2 (east), centre 0, лічильник 0. Погоду провінцій парсер **не** ставить,
    `+0x3E9` не ставить. ✅
* `province = { weather = X }` (`0x56207D..0x5620C9`): `X` → `0x75EAD0`: `clear`→0, **`winter`→1**, `raining`→2,
  `snowing`→3, `storm`→4, `blizzard`→5, `muddy`→6, інше (зокрема `frozen`, якого немає серед ключових слів) → 7 і
  «ERROR : Invalid weather type», але 7 **записується**. ✅ Збереження пише так само (`0x75EB50`: 1 → `winter`).
* Без блоку `weather`: фронтів нема, `static` = 0 (якщо не лишився з попереднього сценарію), усі провінції 0
  (скидання `0x4E3AD4`). Перше оновлення при старті гри (§1, 0x4D) одразу дає зимові провінції frozen і перший фронт. ✅
* Сейв пише `static` і для фронтів `id, provinces, centre, speed, special, heading` (`0x75CFE0`, `0x75F248..0x75F6C6`);
  лічильник `+0x28` — ні (🔎 після завантаження 0).
* Події (команди → повідомлення провінції `0x1B5..0x1B8`, обробник-перемикач `0x4E687F`):
  * `start_pattern which=type value=id where=prov when=W` → `0x75D490`: якщо `isPrecip(where)` або рельєф 9 або
    об'єкт з цим id уже є — нічого; інакше новий фронт: centre = where, provinces = {where}, **speed = 1000000**
    (фактично нерухомий), `special = 1`, heading 2; `prov.w := W` (сире значення). ✅
  * `add_to_pattern` → `0x75D5F0`: рельєф ≠ 9, фронт знайдено, додати where (якщо ще нема), `prov.w := W`. ✅
  * `end_pattern` → `0x75D650` = `ret` — **нічого не робить**. ✅
  * `set_ground which=prov value=V` → `prov.w := (int)V` (`0x4E693E`). Значення `when/value` розбираються
    `0x70B9C4` через ту ж `0x75EAD0`. ✅

## 4. Споживачі

### 4.1 Сухопутний рух ✅ (`0x507FF0`, vtable `0x7E85C0` слот `+0x78`; виклик з `0x430E30(стек, звідки, куди)`; підтверджує land-movement.md §3.2)
Погода провінції **призначення** → рядок `MOV_*` (`0x44D760`, таблиця `0x44D7B0`): 0→35 CLEAR, 1→38 FROZEN,
2→39 RAIN, 3→37 SNOW, 4→40 STORM, 5→36 BLIZZARD, 6→41 MUDDY, інше → без модифікатора. Множник `(1 + mod)`
(`0x508228..0x508250`). WinterSpecialist (біт 3 рис генерала) при погоді 1/3/5: `× (1 + combat[159])`, ваніль 0.05,
`0xDC16AC` (`0x508501..0x508536`), **лише якщо генерал є і дивізій стека не більше за його ліміт** — без генерала
`0x5083A1` переходить у кінець, при перевищенні ліміту `0x5083B3..0x5083CD` (`0x50A330`) обходить усі бонуси
генерала до руху, зокрема зимовий. Флот і авіація: погода на рух не впливає
(інших читачів `MOV_*` за погодою нема). ✅

## 6. Незалежна перевірка: доповнення ✅

Другий прохід підтвердив §1–§4 і додав деталі, важливі для дослівної реалізації:

1. `srand(seed)` на початку оновлення переініціалізовує **спільний** стан `rand()` усієї ігрової логіки (зокрема
   годинника). Тож кожні 6 годин випадкова послідовність гри скидається й далі йде від останнього значення погоди.
   При `static` цього не відбувається. (Реалізація має окремий генератор погоди і цього не відтворює.)
2. Фронт, пересіяний з порожнього списку (`Seed`), обробляється в тому ж оновленні: новий центр отримує свій `r2`
   і поширює опади.
3. Поширення може заходити в морські, річкові (рельєф 9) і вимкнені (`+0x180`) провінції — їх виключає лише `Seed`.
4. Грязюку (6) не змінюють ні FREEZE, ні onset: провінція, що лишилася грязюкою після серпня, сохне лише в теплий
   сезон. В Арктиці вересень (північ) і березень (південь) — водночас onset і warm (onset перевіряється раніше).
5. Видалення з фронту прибирає **перший** вузол із цим значенням (`0x417400`), а цикл зупиняється за значенням
   (`[вузол] == firstNew`). Якщо провінції фронту не мають опадів (моди, події), поширення може додати дублікати —
   навіть сам центр (d = 0 ⇒ X = 1) — і цикл може зупинитися раніше на оригінальному вузлі. У ванільному
   `ardennes.eug` провінції фронту засніжені, тож це крайній випадок.
6. Провінція 0 і морські провінції проходять кліматичний крок; єдиний `rand()` кліматичного кроку — висихання
   грязюки (`0x75DF45`), лише для провінцій із погодою 6 у теплий місяць, у порядку провінцій і до всіх `rand()`
   фронтів.
7. Позиції `combat[n]` перераховано за ванільним `db/misc.txt`: #7 = 0.05, #159 = 0.05, #167 = 0, #169..175 =
   1.0, 1.0, 1.0, 0.8, 0.8, 0.6, 0.7; завантажувач `0x5354D0` кладе значення n на `база + 4·(n−1)`. Нова логіка ORG
   вмикається лише при `combat[167] == 1.0` точно, а її множники діють лише при додатному відновленні.
