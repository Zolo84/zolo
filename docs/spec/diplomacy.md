## 3. Альянси й фракції ✅

### 3.1 Модель
Альянс — об'єкт того ж класу, що й сторона війни: список членів, **перший — лідер** (вийшов лідер — лідером стає
наступний). Фракції — його підкласи (`0x4A7900` — «це фракція»); нумерація в команді й тригері **різна**:
| | Axis `[0xD61582]` | Allies `[0xD61586]` | Comintern `[0xD6158A]` |
|---|---|---|---|
| команда `alliance where = …` | 1 | 2 | 3 |
| тригер `participant = …` | 2 | 1 | 3 |

Інше значення `participant` — «у будь-якому альянсі». Фракційне правило §1.2 (г) дивиться лише Axis і Allies.

### 3.2 Створення й вступ
* CREATE_ALLIANCE (`0x47E420`): новий альянс із засновником. REQ_JOIN_ALLIANCE (сервер `0x5B2DFF`; J — вступник):
```

L := J і члени старого альянсу J, що не в S і ні з ким із членів S не воюють (без альянсу — [J])
для кожного c ∈ L: c в альянсі → EXEC_LEAVE_ALLIANCE;  EXEC_JOIN_ALLIANCE лідеру S (S, c);  ALLIANCE_SUB_OFFER ❓;
                   c вступає у війни лідера, а лідер із союзниками — у війни c (§1.3)
```
* EXEC_JOIN_ALLIANCE (`0x47D4F0`; адресат R, у повідомленні альянс S і країна X): **до членів S додається X**
  (rel[X→кожен член] ≥ −145); альянс R і X := S; rel[R→X] += 20, rel[X→R] := rel[R→X]; новини, депо й ризик
  повстання; перерахунок кешу. **У війни не втягує** — це робить `0x5B0790` у викликача.

C вилучається з S (лідер → наступний), альянс C := 0, масив C+0x34AC обнулено ❓; маріонетки C в S виходять теж. Якщо

## 11. Відкриті питання
1. Завантаження воєн, альянсів і договорів зі сценарію; чи стоїть «воює» на старті; `enddate` війни.
2. Хто ставить дату заборони оголошення (§1.1); ціна оголошення й виходу з альянсу (гроші, dissent); поля політики в
   порогах §1.1; опції гри й байти `0xDC18A8` / `0xDC18A9`; значення байтів `C+0xE8D6`, `C+0x34AC` і поля `+0x284`.
3. Правило звільнення провінції союзника (`0x4E8900`); спадкоємець при анексії, коли ні A, ні окупант не в альянсі.
4. Ліквідація без анексії (COUNTRY_BROKEN `0x4887F0`); мирні пропозиції й умови миру; хто шле PROVGIVEN; SPLIT_WAR,
   WHITE_PEACE, EXEC_DESTROY_ALLIANCE; `alliance where ≥ 4`.
5. Які ключі `revolt.txt` живлять три списки статичних даних тегу (`minimum`, `extra`, третій); `0x44BAD0` (юніти),
   `0x44AE60`, CREATE_COUNTRY докладно; чи справді SetController не чіпає юнітів.

## 12. Незалежна перевірка: поправки ✅
1. **Фракції**: `[0xD61582]` — **Axis** (`where = 1`, `participant = 2`), `[0xD61586]` — **Allies** (`where = 2`,
   `participant = 1`), `[0xD6158A]` — Comintern (3); перший прохід мав Allies і Axis навпаки й однакову нумерацію.
2. **misc**: `0x4A3500` читає `diplomacy[15]` (від нуля — 14), фільтр списку для звільнення, а не повернення окупованих
   провінцій — те `diplomacy[16]` (від нуля — 15), без прямих звертань.
3. **ID 163** зупиняє лише непримусове оголошення (перевірка після `force`) і фракційне правило, не подієвий `war`.
4. **Прапорець «воює»** має другого писача — обробник таблиці відносин на GAME_STARTED.
5. **`0x4A2030`**: заборона, коли rel[A→T] **більше** межі (не менше); за belligerence — коли поріг **більший** за
   belligerence T (рівність проходить).
6. **Крок виходу в `0x5B0790`**: P кидає власні війни проти спільних з Q ворогів (P ∈ S_a, Q ∉ S_a, спільний ворог у
   S_d, і дзеркально), а не навпаки; вступає P лише у війни, де ні з ким з обох сторін не воює.
7. **`alliance`**: коли обидві без альянсу — `0x5B0790(T, C, 1)`, а не `(C, T, 1)`; `where ≥ 4` або фракція без
   лідера — C вводиться у фракцію напряму EXEC_JOIN_ALLIANCE.
8. **EXEC_JOIN_ALLIANCE** додає до членів країну X з повідомлення; адресат лише ставить свій вказівник альянсу.
9. **Мир повертає провінції «з боєм»**: belligerence власнику, −0.75 окупанту, будівлі до 10 % (слот 5 — 50 %),
   видобуток 0; так само в капітуляції й окремому мирі при виході з альянсу.
10. **PROVGIVEN**: для не-ядра — попередній націоналізм провінції, обмежений 30, а не значення від SetOwner.
11. **Анексія**: −40 (байт X про V) **або інакше** −25 (байт X про A), не обидва і не байт A про X; окупант отримує
    провінцію, лише якщо його альянс ≠ альянсу A (дві неприєднані — «однакові»); перенос забирає ще людські ресурси
    й чергу виробництва.
12. **END_MASTERY** обнуляє байт у масиві маріонетки (`which+0x34AC+C`), а не сюзерена.
13. **Незалежність, список 3** перевіряє власника (не контролера) і завжди виключає ядра й претензії R.
14. **JOIN_WAR** нараховує belligerence тим, хто першого дня стає на бік атакувальників, незалежно від b1: «подієвий»
    `war` звільняє від неї лише самого оголошувача.
15. Підтверджено: маршрутизація, misc і ID країн, запис відносин (зміщення events.md / land-movement.md — ті самі байти
    від `D + 44·j`) і кеш; перевірки й злиття воєн; WE/THEY_DECLARE, belligerence, +2 interventionism гарантам жертви;
    мир «сторона зі стороною»; SetController, SetOwner; альянси; анексія, `make_puppet`, `independence`, `civil_war`;
    адресат `inherit` — C; дані трьох прикладів.
