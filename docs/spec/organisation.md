# Специфікація: відновлення організованості (ORG) дивізії (DH 1.05.1)

Позначки: ✅ простежено в коді, 🔎 ймовірно/виведено, ❓ невідомо.

**Статус перевірки.** Усе, що позначено ✅, незалежно перевірено вдруге за дизасемблером (§8): жодне твердження не
спростовано; уточнено умови на морі/річці, країну множника відстані, правила «дружності» нової логіки, кеш опорної
провінції й точність обчислень. Реалізація — `dh-sim::org` (`OrgRegain`).

Нумерація `combat[n]`/`economy[n]`/`country[n]`/`mod[n]` — 1-based позиції значень у секції ванільного
`db/misc.txt` (підраховано за файлом: economy 87, intelligence 16, diplomacy 16, combat 263, …).
Структура misc у пам'яті: economy[1] … economy[87] = `+0x1B838`, intelligence[1] = `+0x1B83C` (✅ `0x78B69B`),
combat[1] = `+0x1B8BC` (✅ `0x789F95`), combat[n] = `+0x1B8BC + 4·(n−1)` (✅ для 165, 166, 168, 191 —
`0x78A9B5`, `0x78A9C1`, `0x78A86F`, `0x78A97B`).

## 4. Підсумок для ванілі (сухопутна дивізія, стара логіка)

Пояснення в словах: приріст за годину = 0.1·(1+d)·[мін. 0] з x, що складається з добутку
ESE·(1+(мор−30)/100)·(дружня ? min(2·інфра,1.2) : інфра)·(0.5 якщо reinforcing)·(0.5 якщо без пального)·D·
(3/2/1/0.5 за q) + (мор−30)/100 − погода, далі ×міністр. Рух (не відступ) → −0.02/год; невдача списання припасів
або «не в постачанні» → −0.05/год (до складності); погода віднімається і від від'ємних значень.

Приклад: піхота (мор 30), дружня провінція інфра 0.6, ESE 1.0, D = 1, q = 0.1, ясно, NORMAL:
x = 1·1·min(1.2, 1.2)·3 = 3.6 → 0.36 ORG/год = 8.64/добу.

## 8. Незалежна перевірка: уточнення ✅

1. **Море й річка (стара логіка):** `x = 0`, коли стек не в провінції (`+0xC ≤ 0`) **або** рельєф провінції 8/9
   (Ocean/River) — не лише на транспорті.
2. **Множник відстані D** бере країну **власника стека** (`+0x248`), не дивізії; якщо власника нема, множник
   `+0xE858` пропускається. `dist = 0`, якщо опорна провінція S — поточна. `+0xE858` (= `country[10]` на старті)
   змінюють події/команди (`0x4906CA..0x490712`, мінімум 0.01).
3. **Бонус міністрів до моралі** множиться лише при `x > 0` (строго) і наявності країни командування (`0x5224F0`).
4. **Нова логіка, провінція:** при стеку на суходолі (`+0xC > 0`) рельєф 8/9 або провінція без власника — **жодного**
   множника; інакше «дружня» = `0x44A650(власник P, власник стека)` (та сама країна → так; запис відносин `+0x20`
   ≠ 0 (🔎 війна) → ні; `+0x26` → так; маріонетка в будь-який бік → так; інакше байт `+0x25` 🔎 «союз») або військовий
   доступ власника стека → `× combat[192]`, інакше `× D`; на транспорті `× combat[193]`. Множник відступу
   `combat[195]` діє лише всередині гілки «рухається».
5. **Споживання в новій логіці** — до перевірки бою: пальне, лише якщо `+0x10C·+0xF0·0.01 > 0`, припаси — якщо
   `+0x108·+0xF0·0.01 > 0`; інакше відповідний прапорець скидається.
6. **Кеш опорної провінції `+0x142` (`0x51D3D0`):** «опорна» = власник провінції існує і (це власник стека або
   `0x44B2C0(власник, країна командування)`, байт відносин `+0x25`) — без перевірок доступу й вказівника альянсу.
   Якщо поточна провінція опорна — кеш := поточна. Інакше, поки кеш порожній, шукається найближча опорна серед
   0..map[2]−1: за замовчуванням столиця (`0x44E170`), найкраща відстань спершу 1 000 000 (ціле); заміна лише при
   `dist < best`, після чого `best := trunc(dist)` (тож провінція ближче ніж за 1 одиницю (100 км) зупиняє пошук).
   Непорожній кеш у неопорній провінції не оновлюється. Другий виклик — `0x51B359` (вивантаження з транспорту).
7. **Точність:** кожне збереження `x` — f32; результат старої логіки лишається на стеку FPU (double, 53 біти —
   керувальне слово CRT `0x27F`), і лише `ORG + r` округлюється до f32 у циклі; результат нової логіки — f32.
8. **Підказка інтерфейсу** (`arg = 0`) не списує припаси, але переписує прапорці `+0x156/+0x157`.
9. **Мод «Darkest Hour Full»:** `combat[229]` = 0.35 (ORG після висадки з не-транспортного носія).
10. Фолбек бонусу міністрів за бригадами (`combat[164] = 1`): `max(0, найбільше ненульове значення бригад)`;
    значення повзунка зберігається як «значення у файлі − 1» (0..9, `0x760548`).
