# Darkest Hour — повне відновлення алгоритму «XOR-дешифрування» ресурсів та розбір «MIDI»-плеєра (MCI)

Об'єкт: `Darkest Hour.exe` (MSVC6, image base 0x400000; 1:1 копія Steam-версії, sha256 `7a1ae8bb…51eb4`).
Діапазон 0x740c70–0x7413f0 (декомпіляції `/tmp/dh-decomp/00740c70…007411f0*.c`, асемблер `/tmp/dh-disasm.txt`).
Таблиці зчитано напряму з `.data` бінарника (PE: `.data` VA 0x42c000, Raw 0x42c000; VA→raw = VA−0x400000 у межах секції).
Виконуваний скрипт: **`/tmp/dh-xor.py`** (відновлені генератор, перевірка, сканер інсталяції).

**TL;DR:** «дешифрування» — це не XOR і не дешифрування файлів, а спадна з EU2-епохи **перевірка інсталяції/CD з 32-байтовим підписом** (permutation+віднімання+контрольна сума). У збірці Darkest Hour цей код **повністю мертвий**: WinMain викликає `FUN_007411f0(0)`, а всі case 1–4 недосяжні. У Steam-інсталяції файлів-маркерів немає, жоден із 46 082 файлів гри не несе підпису, `GBME.wav` — звичайний RIFF/WAVE. «MIDI-плеєр» (0x5797a0–0x579ec0) насправді відкриває **MCI-пристрій CD Audio** (`MCI_DEVTYPE_CD_AUDIO = 0x204`) і грає **аудіо-дорожки компакт-диска**; MIDI-дані гра нікуди не передає.

## 1. Алгоритм (адреси 0x740c70–0x7413f0)

### 1.1 Таблиці у `.data` (зчитано з `Darkest Hour.exe`)

| Адреса | Вміст |
|---|---|
| `0x874228` | **P[0..31]** — 32 dword-позиції (перестановка): `177, 183, 151, 94, 51, 100, 101, 231, 67, 200, 223, 178, 2, 19, 62, 65, 43, 64, 78, 191, 32, 44, 56, 12, 7, 250, 120, 134, 137, 166, 17, 13` |
| `0x8742a8` | **K[0..7]** — 8 байтів ключа (крок 4 байти): `23, 222, 243, 27, 7, 253, 64, 255` |

Loop: `i = 0..31`, індекс ключа = `i & 7` (з mod-корекцією для знаку в коді), позиція = `P[i]` (читається dword з `0x874228+i*4`).

### 1.2 Перевірка файлу — `FUN_00740f60` @ 0x740f60 (і 3 інлайн-копії у case 1, 0x741041–0x741390)

```
для i = 0..31:
    O[i] = F[ P[i] ] - K[ i&7 ]          (mod 256, SUB — НЕ XOR!)
    sum  = sum + F[ P[i] ]               (mod 256)
валiднiсть: sum == F[0];  інакше FUN_007a64d3(0)  // exit(0)
```
- Читається лише перші **0x200 = 512 байт** файлу (`fopen(…,"rb")`, `fread(1,0x200)`).
- **Контрольна сума** = сума 32 «сигнатурних» байтів mod 256; зберігається у **байті 0 файлу**.
- **Розмір блоку**: 32 байти; вони РОЗКИДАНІ по перших 512 байтах файлу (позиції `P[i]`), решта 480 байтів (і весь файл) — звичайний вміст.
- Результат `O[0..31]` кладеться в глобал `0xd4bcec` (більше ніким не читається — мертвий вивід).

### 1.3 Генератор підпису (installer-бік) — `FUN_00740ea0` @ 0x740ea0

```
buf[0..255] = rand()&0xff            // 256 випадкових байт (0x7a7c0e = rand)
для i = 0..31:
    buf[ P[i] ] = S[i] + K[ i&7 ]    // S — рядок (до 31 симв.), читається зі зсуву 0x100 файлу
buf[0] = sum(buf[ P[i] ])            // контрольна сума пишеться останньою
```
Викликається лише з `FUN_00740fc0` @ 0x740fc0 (читає `avi\euintro.avi` до 0x73ef0a байт, генерує таблицю з рядка на зсуві 0x100, перезаписує файл) — **штампування файлу при інсталяції/CD-master**. У Darkest Hour **не викликається взагалі** (0 xref).

### 1.4 CD-перевірка (спадщина EU2)
- `FUN_00740d70` @ 0x740d70 — скан приводів `A..Z` (`GetDriveTypeA==5` = CD-ROM), на CD шукає файли `d:\1111.VPP…4444.VPP` (буква диска підставляється), інакше `MessageBox("EU CD not found. Please insert CD in drive.", "Error", Retry|Cancel)`.
- `FUN_007410d0` @ 0x7410d0 — перевірка файлу: об'єкт-відкривач (`FUN_00426f50`, 0x13e байт), порівняння **розміру файлу** (`[obj+0x138]`) з очікуваним; невдача → `MessageBox("EU2 CD not found.", "Error")` + `exit(0)`.

### 1.5 `FUN_007411f0` @ 0x7411f0 — диспетчер case 1–4 (jump table @ 0x7413d8)

| case | файл | розмір |
|---|---|---|
| 1 | `map\incognita.tbl`, `sfx\wave\gbme.wav`, `gfx\interface\cover65.bmp` | по 512 байт, перевірка §1.2 |
| 2 | `music\tmp.dat` | **0x1975400 = 26 677 248** |
| 3 | `avi\paradox.avi` | — |
| 4 | `accessories\win95\ws2setup.exe` | 0xf0d20 |

**Ключовий факт:** єдиний виклик — з WinMain @ `0x793152`: `mov [ebp-0x72c],0; push [ebp-0x72c]; call 0x7411f0` → `param_1 = 0`, switch не виконує жодного case (default → ret). **Увесь блок 0x740c70–0x7413f0 — мертвий код у цій збірці** (це й дозволяє Steam-версії працювати без CD і без цих файлів). У версіях гри з активною перевіркою файли не «шифрувалися б» — лише 32 байти підпису всередині перших 512 байт.

## 2. Практична перевірка на реальних файлах (Steam-інсталяція)

Шлях: `/home/andriy/.local/share/Steam/steamapps/common/Darkest Hour A HOI Game/`, exe ідентичний проаналізованому (sha256 збігається).

| файл | стан | підпис (§1.2) |
|---|---|---|
| `sfx/wave/GBME.wav` | **існує**, 27 910 байт, початок `RIFF…WAVEfmt ` (звичайний WAV) | **НІ** — `F[0] != Σ F[P[i]]`, decode32 нечитабельний |
| `music/tmp.dat` | **НЕМАЄ** на диску | — |
| `avi/paradox.avi` | **НЕМАЄ** (є лише publisher/paradox/game.bik + binkplay.exe) | — |
| `map/incognita.tbl`, `gfx/interface/cover65.bmp` | **НЕМАЄ** | — |

**Скан усієї інсталяції** (46 082 файли, `/tmp/dh-xor.py`): файлів, що задовольняють контрольну суму `F[0] == Σ F[P[i]] mod 256` **і** дають читабельний декод — **0 (нуль)**. Тобто в цій версії гри **немає жодного «зашифрованого» файлу — розшифровувати нема чого**, а сам алгоритм відновлено повністю й підтверджено round-trip-тестом (генерація → перевірка → декодування, `/tmp/dh-xor.py` [0], assert проходить).

Наслідок: `music\tmp.dat` — **не «MIDI-архів»**: це файл-маркер CD-перевірки фіксованого розміру (26 677 248 байт = 0x1975400, перевірка розміру в `FUN_007410d0`), прибраний із Steam-релізу. Ніякого контейнера з треками в ньому коду не передбачено.

## 3. «MIDI»-плеєр 0x5797a0–0x579ec0 — насправді CD-Audio (поправка до RE-audio-video.md)

### 3.1 Що показує код (`mciSendCommandA` = IAT `0x7e3268`, `timeGetTime` = `0x7e3254`)

1. `0x5797e6` (ctor @ 0x5797a0): `mciSendCommandA(0, MCI_OPEN=0x803, MCI_OPEN_TYPE|MCI_OPEN_TYPE_ID=0x3000, &parms@0xbd00f8)` з `lpstrDeviceType = 0x204`; **`lpstrElementName = NULL`** (0xbd0104 ніколи не пишеться), образу рядка-елемента немає.
   - За SDK: `MCI_DEVTYPE_CD_AUDIO = MCI_STRING_OFFSET(512)+4 = 0x204` → **відкривається CD Audio, а не MIDI sequencer** (sequencer = 0x20B). Раніше звіт припускав «MIDI»; це припущення не підтвердилося.
2. `0x5797f6` + `0x57982a`: після успіху — `MCI_SET(0x80d)`, `MCI_SET_TIME_FORMAT`, `dwTimeFormat = 0x0a` = **MCI_FORMAT_TMSF** (track:min:sec:frame — формат CDDA/sequencer).
3. `FUN_00579a20` (викликається з ctor і як refresh): `MCI_STATUS(0x814)` з `dwItem=3` = **MCI_STATUS_NUMBER_OF_TRACKS** → кількість доріжок у пристрої (cap 100, `+0x6`), далі на кожну доріжку `dwItem=1` (**MCI_STATUS_LENGTH**) + `dwTrack=i`; з TMSF-довжини зберігаються: тривалість `word [+8+i*2]` (≈ хв·60+с, тикер множить на 1000) і три компоненти TMSF у таблиці `+0xd0/+0x198/+0x260` (по word/byte на доріжку).
4. `FUN_00579b30` @ 0x579b30 (грати доріжку `n`): `local_4 = TMSF(n, byte@260, byte@198, word@d0)`; `mciSendCommandA(dev, MCI_PLAY=0x806, MCI_NOTIFY|MCI_FROM|MCI_TO=0xd, {dwCallback=hwnd, dwFrom=TMSF, dwTo=0})`; фіксує `timeGetTime()` у `+0x32c`, поточний/минулий трек `+0x328/+0x32a`.
5. Решта класу: `0x579cc0` (випадковий трек `rand()%n+1`), `0x579cf0`/`0x579d60` (випадковий з виключенням списку, −1-терміновані), `0x579e30` (тикер: поки `elapsed < dur*1000 мс` — «грає»), `0x579c00` (MCI_PAUSE/MCI_RESUME 0x809/0x855), `0x579c80` (MCI_STOP 0x808), `0x579850/0x5798d0` (деструкти, MCI_CLOSE 0x804), `0x579940/0x5799b0` (reopen). Об'єкт — частина аудіо-движка `DAT_00bd0e18` (0x16414 байт, vtable 0x7ead78/0x7ead88), прапорець увімкнення `+0x4`, стан паузи `+0x5`, ID пристрою — глобал `DAT_00bd00fc`.
6. `FUN_00579770` @ 0x579770 (WinMain, рядок 571) — це **не конструктор MIDI**: просто скан букв `C..T` на `GetDriveTypeA()==DRIVE_CDROM` (пошук CD-приводу перед музикою).

### 3.2 Як «дані потрапляють» у MCI — відповідь
**Ніяк через гру.** У бінарнику немає: рядків `.mid`/`sequencer`/`rmi`, сигнатури `MThd`, `GetTempPath/GetTempFileName`, запису `CreateFileA/WriteFile`, елемента в `MCI_OPEN`. Гра відкриває **cdaudio-пристрій за типом** і грає **фізичні аудіо-дорожки компакт-диска** (альбомна CDDA-семантика: NUMBER_OF_TRACKS, per-track LENGTH, PLAY FROM TMSF track). Джерело музики = диск у CD-приводі; без CD (типова Steam-ситуація) `MCI_OPEN` не вдається (`DAT_00bd00fc=0`), треків 0 — музика мовчить, гра не падає. Той самий механізм вимагав CD у класичних EU2/HoI2 (звідси «EU2 CD not found» у §1.4).

## 4. Відповіді на питання задачі

| Питання | Відповідь |
|---|---|
| XOR-ключ? | Ключ — 8 байт `K=[23,222,243,27,7,253,64,255]` на `0x8742a8`, але операція — **віднімання** `F[P[i]] − K[i&7]` (аналог XOR-шифру зсувом), таблиця позицій `P` на `0x874228` |
| Контрольна сума? | `Σ F[P[i]] mod 256 == F[0]` (перший байт файлу = сума 32 підписних байтів) |
| Розмір блоку? | 32 байти на файл; читається перші 512 байт, решта файлу не «шифрується» |
| Реальні файли? | `GBME.wav` — чистий WAV без підпису; `tmp.dat`/`paradox.avi`/`incognita.tbl`/`cover65.bmp` відсутні; 0 з 46 082 файлів несуть підпис → **розшифровувати нема чого**; весь механізм викликається з `FUN_007411f0(0)` = мертвий код |
| tmp.dat формат? | Не контейнер і не MIDI-архів — маркер CD-перевірки (точно 26 677 248 байт) |
| MIDI через MCI? | Це **CD Audio** (`MCI_DEVTYPE_CD_AUDIO=0x204`); треки = доріжки CDDA; дані у MCI не передаються |

Файли: звіт `re/RE-xor-midi.md`, скрипт `/tmp/dh-xor.py` (таблиці, verify/decode, round-trip, сканер).
