## 1. Файли та структура каталогів

Шлях у грі: `gfx\fonts\%d\%s` (рядок `s_gfx_fonts__d__s_0082f03c`), де `%d` = номер мови з `settings.cfg` (глобал `DAT_00dc1544`), `%s` = ім'я файлу з `.bmp`. Якщо підпапки немає — fallback `gfx\fonts\%s` (рядок `s_gfx_fonts__s_0082f050`). Тобто `gfx/fonts/` = англійська (мова 0), `5/` = мова 5, `7/` = мова 7.

`<GAME>/Mods/Darkest Hour Full/gfx/fonts/` **не існує** — шрифти завантажуються з кореня гри незалежно від мода.

Всього **24 файли**: 8 імен × 3 набори (root, `5/`, `7/`):

(усі 8bpp; точні розміри файлів наведено лише для root-колонки, у 5/ і 7/ відрізняються на 2–120 байт)

**Висота стовпця** в наборі 7/ завжди = `223 × W` рівно (3122=223×14, 2230=223×10, 5352=223×24, 1784=223×8). У root/5/ у частини файлів є зайві рядки: 3140=223×14+18, 4028=223×18+14, 4472=223×20+12, 5360=223×24+8, 3108=**222**×14 (без останньої клітинки!). Це поля/хвіст, які завантажувач просто не читає (читає рівно `223 × stride × W` байт зверху зображення).

## 2. Формат BMP у файлі

- Класичний BMP: `BM`, BITMAPINFOHEADER (biSize=40), **8 біт на піксель (палітровий)**, без стиснення (biCompression=0), палітра 256×4 (BGRA, offBits=1078), `height > 0` → bottom-up (рядки у файлі знизу вгору).
- Прозорість: **індекс 255 (0xFF)** — у палітрі це пункт (B=0,G=255,R=0,A=0) — «зелений»; код перевіряє саме значення байта `== 0xFF`, а не альфу.
- Фактичні pixелі: лише індекси, що використовуються: 0 (чорний? у палітрі 1=білий), індекси гліфів 1..15 та 0xFF. Колір гліфа при відтворенні задається кодом (див. §5), а не палітрою.
- У пам'яті движок перетворює зображення в **top-down** буфер з рядком-stride `((bpp*W + 7)/8) & ~7` (=16 для W=14, 8 для W=8, 24 для W=18/20/24…), 8-байтове вирівнювання (FUN_0040e9e0 → FUN_0040eb60; vtable CImage = `PTR_FUN_007e34f8`).

## 3. Розкладка гліфів у зображенні

- Зображення = **один стовпець квадратних клітинок W×W**, де W = ширина зображення = номінальний розмір шрифту (8/10/14/18/20/24).
- **223 клітинки** = символи `0x21..0xFF` у порядку коду (секвенційна розкладка «клітинка k = символ 0x21+k»). Завантажувач ініціалізує таблицю для цих кодів; `0x00..0x20` не мають гліфів (пробіл 0x20 → ширина за замовчуванням = W).
- Гліф у клітинці вирівняний **донизу** клітинки: верх клітинки порожній (висота літери менша за клітинку), «хвіст» букв (p, q, y — у цього шрифту немає) — не спостерігався. Приклад (7/euro14, літера 'A', клітинка 32, 14×14):

```
..............
..............
..............
..............
..#...........
.#.#..........
.#.#..........
.#.#..........
.#.#..........
.###..........
#...##........
#...#.........
..............
..............
```

- Кодування гліфа в пам'яті (FUN_00411259): **RLE 4+4 біти** — один байт = `(run_length-1) << 4 | color_index`, де color 0 = прозорий (джерельний 0xFF), колір = молодша тетрада індексу палітри (гліфи тільки 0..15). Байти йдуть по рядках клітинки, потік безперервний, рядок перегортається через `W`. Максимальний run = 16, довші серії розбиваються.
- Структура гліфа в пам'яті — **8 байт**: `[0]` = вказівник на RLE-дані, `[+4]` = розмір RLE (ushort), `[+6]` = **ширина символу** (ushort, = права колонка з чорнилом + 1; якщо клітинка порожня → 1).
- **Пропорційний шрифт**: ширина кожного символу = «правіша непуста колонка + 1» (виміряно: 7/euro14: '!'→1, 'i'→2, 'l'→2, 'm'→8, 'w'→8, 'A'→6, '0'→5; root/euro14: 'i'→3, 'm'→8, 'A'→7, '0'→7; 7/euro24bold: 'A'→17, 'm'→18, 'i'→6, '0'→12). Після кожного символа курсор x зсувається на цю ширину — звідси щільний «конденсований» вигляд.
- `FixNum` (eurostilecond14FixNum): ті самі 223 клітинки, але цифри 0-9 намальовані на всю ширину (з великими засічками, «1» із серіфом) — фактично «моноширинні цифри» для таблиць.

## 4. Завантажувач (FUN_00411598 @ 411598)

Сигнатура: `FUN_00411598(this, name, cellH, charset)`:
1. `sprintf` шляху `gfx\fonts\%d\%s` (мова, name), за потреби `gfx\fonts\%s`; відкриває файл (FUN_007a6615). Помилки: `"couldn't find FONT: %s"`, `"bitmap error: %s"`.
2. Вантажить BMP через CImage-клас: FUN_0040e950 (конструктор) → FUN_0040e9e0 (FUN_0040f470 — парс заголовка: 'BM', planes==1; FUN_0040eb60 — декодування в top-down буфер, stride з 8-байтним вирівнюванням; підтримує 1/8/16/24 bpp).
3. Зберігає: `font+0x04` = ширина зображення W (дефолтна ширина/крок для відсутніх символів), `font+0x10` = cellH (висота рядка; у грі = W), `font+8` = **таблиця символів**: `operator_new(0x400)` = 256 покажчиків по 4 байти, індекс = код символа.
4. Спецзапис `table[0x80]` (ширина = W/6) — перекривається циклом далі, актуальний лише якщо 0x80 немає в charset.
5. Цикл `0x21..0xFF` (або по рядку `charset` — тоді клітинка k відповідає символу `charset[k]`, тобто порядок можна переозначувати): для кожної клітинки — об'єкт гліфа (FUN_00411210, 8 байт), `FUN_00411259(glyph, stride, W, cellH, src)` — RLE-кодування і вимір ширини; крок по джерелу `stride × cellH` байт на клітинку.
6. Буфер бітмапа звільняється; гліфи живуть у таблиці.

Другий клас шрифтів (FUN_00411b53, vtable `PTR_FUN_007e35c0`): таблиця гліфів на `+0x14` (256×4), одиничний гліф вантажиться через FUN_00414c80 (0x7E байт, FUN_00415bd0 — ширина) — схоже на GDI/системний шрифт [використання в DH не простежене].

## 5. Малювання тексту (FUN_00411e4d @ 411E4D)

`FUN_00411e4d(font, text, x, y, clipRect, surface(CImage), color)` — головний рендерер, 1 байт = 1 символ, завершення `\0`:
- Шукає гліф `table[код]`; якщо немає → ширина = `font+0x04` (W), нічого не малює.
- **RLE-декод**: повторює `(байт>>4)+1` разів: `(байт&0xF)==0` → просто пропуск (прозоро), інакше запис пікселя в поверхню `dst[row*pitch + col]`. Для 16bpp — ushort-запис `color`; для 8bpp — запис індексу кольору. Після символа `x += glyph_width` (пропорційно).
- `\n`/`\r` (також `\`+`n` як escape) → `y += font+0x10`, x = початок рядка. `%`+пробіл = екранований символ.
- **Кольорові теги** — символ `§` (0xA7) + літера: `Y`=(0xd0,0xe8,0xf8) світло-блакитний, `W`=білий, `Z`=чорний, `G`=(0,100,0), `R`=червоний, `N`=(0xff,100,100), `M`=(100,0xff,100), `A`=(0,0x40,0), `B`=(0,0,0xc0), `C`=(0x80,0,0), `D`=жовтий, `E`=пурпурний, `F`=(0xff,0x80,0) помаранч, `H`=сірий, `I`=синій, `J`=(0,0xc0,0); `§§` = повернення попереднього кольору (через FUN_00584270). Формат `%RGB`? — ні, `§`+літера.
- **Тінь/контур**: якщо `*(font+0x414) != 0` — поруч із кожним пікселем додатково пишеться чорний (0) піксель на ряд нижче (зміщений на `pitch+1`) — накладний ефект для титулів.
- Кліпування: прямокутник `clipRect` (param_5) — гліф частково за межами пропускається; `surface` — CImage з полями `+0x0c` = bpp, `+0x18` = stride.
- **FUN_00413509** = обгортка «текст по центру»: `FUN_004129c4(text)` (вимір ширини тексту — сума ширин гліфів), `x -= width/2`, вмикає shadow-режим, викликає FUN_00411e4d.
- Загальний бліт спрайтів CImage (для решти графіки) — FUN_00406300: кліп через FUN_004061a0, диспетчер конверсій 8bpp→16bpp: FUN_00406960/00406a30/00406c00/00406eb0/00407180/00407450/00407720. Текст пише в поверхню напряму, без цього бліта.

Текст у грі — 1 байт/символ, коди 0x21..0xFF; тому шрифти й покривають рівно цей діапазон.

## 6. Не-ASCII символи (кирилиця/європейські)

Набори розрізняються вмістом клітинок (перевірено поелементно, розкладка 0x21+k):

- **root (EN) і 5/ (PL):** послідовність у стилі CP1250 (західно/центральноєвропейська): 0xC0 = À (A з гравісом), 0xDF = ß, діакритики за місцями CP1250; порожні (рідкісні) клітинки — 0xD0(Đ?), 0xD7, 0xDE, 0xF0, 0xF7, 0xFD, 0xFE, 0xFF тощо. **Кирилиці немає.**
  - Набір **5/** додатково має польські літери: 0x8F = Ź, 0xA5 = Ą, 0xAF = Ż, 0xB9 = ą, 0xBF = ż (у root ті самі позиції порожні). root/еuro14: 27 порожніх клітинок, 5/: 24.
- **7/ (RU):** повний CP1251: А..Я (0xC0–0xDF), а..я (0xE0–0xFF), вкл. Ё (0xA8)/ё; **українські**: І (0xB2), і (0xB3), ґ (0xB4), Є (0xAA), є (0xBA), Ї (0xAF); сербські/додаткові 0x80–0x9F заповнені. Виняток: **0xBF (ї) = суцільний чорний квадрат** (заглушка художника). У 7/ усі 223 клітинки непусті (крім 7/euro10: порожні 0x5F '_' і 0xA0 NBSP).
- arial8 root: порожні лише 0xA0, 0xFE, 0xFF (тобто 'ю','я'-позиції CP1251 порожні — набір європейський); 7/arial8: 0xFF = 'я' присутня.
- Висновок: **український текст повністю відтворюється набором 7/ (RU)** (крім ї → квадрат), набір root — без кирилиці взагалі.

## 7. Папки 5/ і 7/ = мова з settings.cfg

`settings.cfg` (корінь гри), перший рядок: `0 # LANGUAGE (0 = English, 1 = French, etc.)`. FUN_00791fe9 (ініціалізація) читає це значення (<10) у `DAT_00dc1544` → підставляється в `gfx\fonts\%d\%s`. Порядок мов у `config/text.csv`: English(0), French(1), Italian(2), Spanish(3), German(4), Polish(5), Portuguese(6), Russian(7), Extra1(8), Extra2(9). Отже: **5/ = польський** (підтверджено літерами ĄŹ), **7/ = російський** (підтверджено кирилицею CP1251) — `5/` за змістом майже копія root (відмінність лише в літерах 0x8F/0xA5 і 2 байтах розміру), `7/` — окрема генерація (інша метрика: 10px-версія вужча — 10 пікселів проти 14 у root). **[?]** Точна відповідність номерів мов іншим мовам DH (крім 5=PL, 7=RU) не перевірялась.

## 8. Перевірені дрібниці та відкриті питання

- Висота клітинки (param_3 завантажувача) = ширина зображення (квадратні клітинки) — підтверджено тим, що для всіх файлів крок = W, включно з 7/euro10 (10px) і root/euro10 (14px!). Root eurostilecond10 — 222 клітинки × 14px (не 223) — файл «неповний» [причина ?].
- '5/' eurostilecond10/14/etc на 2 байти менші + biClrUsed=256 (у root 0) — дрібні відмінності палітри/інструмента.
- Зайві рядки root-версій (18/14/12/8) + великі порожні смуги знизу зображення (до ~86 рядків у 24bold) — завантажувач читає top-anchored 223×W×stride, «хвіст» ігнорує.
- FUN_004136a0 (реєстрація шрифту за ім'ям, напр. `fun_00752650 → FUN_004136a0("eurostilecond14.bmp")`) не декомпільована — точні аргументи (cellH=W, charset=NULL) виведені з піксельних даних, а не з коду.
