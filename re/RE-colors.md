## 1. Формула (джерело істини — жива пам'ять гри)

```text
колір_пікселя = palette565[ (LUT[light − off] << 6) | scale ]
```

де:
- `light` — 6-бітне значення освітлення пікселя з lightmap (0..63; типові
  значення океану 19/24 — див. re/RE-lightmap.md §6.2);
- `off` — поле провінції `+0x13E` (у грі стабільно 15);
- `scale` — поле провінції `+0x142` — індекс колірної шкали (0..63);
- `LUT` — таблиця `0xAA41CB` (256 Б): `LUT[i] = clamp(i + 47, 4, 127)`
  (для від'ємних i — насичення знизу: i=-64..-1 → 4..46);
- `palette565` — палітра `0xA44C34`: 8192 × u16 LE (RGB565),
  індекс = `(рівень << 6) | шкала` — 128 рівнів × 64 шкали;
  рядок = LUT-значення (4..127), стовпець = шкала провінції.

Код-джерело: `decomp/004dc010_FUN_004dc010.c` (рядок 77):
`uVar9 = (LUT[(param_4 >> 0x10) - iVar7] << 6) | (iVar2 * 2 >> 1);`
де `iVar7 = *(int*)(prov + 0x13E)`, `iVar2 = *(int*)(prov + 0x142)`,
`param_4 >> 0x10` = light пікселя (16.16 фіксована точка).

## 2. Генерація палітри з colorscales.csv (FUN_004d7db0)

- Адреса `0x00A44C34`, 16384 Б = 8192 × u16; **генерується в runtime**
  (у меню нульова, заповнюється при вході в сценарій).
- Стовпець `col` = номер блоку з colorscales.csv (0..31); стовпці 32..63 = ті самі
  блоки **× 0.5** (темна половина; саме сюди веде біт 0x20 у scale).
- Канал блоку: лінійна інтерполяція між контрольними точками (index 0/20/40/64),
  потім нелінійна крива та пакування RGB565:

```text
v' = min(0.9·(0.00234375·v² + 0.5·v), 255)
565 = ((r'>>3)<<11) | ((g'>>2)<<5) | (b'>>3)
```

  Константи exe: 0.00234375 (`_DAT_007e7f78`), 0.5 (`_DAT_007e3358`),
  0.9 (`_DAT_007e40a8`).
- Верифікація проти дампа живої пам'яті (8192 записи): **49% точно, 94% у межах
  ±1 кроку RGB565** (Δ≈8 на канал); block рамок border/borderOutline — 100%.
  Залишковий ±1 — точний rounding exe (можливо, fixed-point) — відкрите.
- Контрольні (дамп 1933 / білд з файлу — тест `generated_palette_matches_memory_dump`):
  Польща col 8 (жовта родина: 248,240,200 біля L0), СРСР col 53 (DarkRed|0x20 =
  (88,4,24) при L≈48-52), Німеччина col 42 (Gray|0x20 ≈ (64,64,64)), море col 55
  (water|0x20: рампа (56,80,88)→(8,16,16), L 32..96).

## 3. scale провінції — З ВЛАСНИКА (FUN_004dcb20 case 0 → FUN_004e8a40)

- Перебір провінцій 1..N (PROV0 не чіпається) при кожному оновленні політичної карти:
  - **власник є** → scale = номер блоку кольору власника з country.csv
    (`FUN_004aee40`, таблиця з §0);
  - **вода** (Terrain Ocean/Water) → 23;
  - **без власника** → 2;
  - потім `FUN_004e8a40`: якщо провінція **не видима гравцеві** — `scale |= 0x20`
    (темна половина палітри; FUN_00654700 — маска видимості). Спостережено на живій
    грі: власні провінції гравця — світлі, усі іноземні та море — темні.
- Підтвердження на дампі 1933 (2769 записів): POL 221-258 → 8 (світлі);
  СРСР → 53; Німеччина → 42; морські (607) → 55; PROV0 → 34 (2|0x20).
- Відкрите питання: у пізніших сейвах — чи союзники/розвідані регіони світлішають
  (перевірити після військових подій). У 1933 усі іноземні темні, включно з союзниками.

## 4. LUT (0xAA41CB)

- Розмір 256 Б; знімався з контекстом від'ємних індексів:
  `LUT[i] = clamp(i + 47, 4, 127)`.
- `LUT[0] = 47`, `LUT[80..] = 127` (насичення), `LUT[-64..-43] = 4` (насичення знизу).

## 5. Поля провінцій (base 0x0B770024, запис 0x4B2 Б)

| зсув | тип | сенс | у грі |
|---|---|---|---|
| +0x13E | int | off — зсув освітлення | 15 (стабільно) |
| +0x142 | int | scale — колірна шкала | 8=Польща, 42=Німеччина, 53=СРСР, 55=море, 34=PROV0 |

Морські провінції мають **scale 55 = 23|0x20** (вода + невидимість) — саме ним гра
рендерить воду: спостережений на екрані темно-бірюзовий (49,73,82) є в дампі палітри
як col 55 при L≈38-39; широкий океан у lightmap належить id морських зон
(напр. 2327, 2339, 2420, 2725), а не PROV0. (Попередня версія «вода = шкала 12» —
**ХИБНА**, походила зі старого інтернет-скріншота й фіта палітри, а не з дампу
полів провінцій.)
