# Darkest Hour.exe — Збереження/Завантаження та Стиснення (BZ2)

Джерело: декомпіляції Ghidra у `/tmp/dh-decomp/` (файл = адреса функції), рядки `s_*` з адресами у коді, `/tmp/dh-strings.txt`. Все нижче — лише з коду.

## 1. Завантажувач libbz2.dll — FUN_0040f5a0 @ 0x40f5a0

Функція-ініціалізатор (викликається з прапором-станом `*(int*)(param_1+4)`, повертає 1 якщо вже завантажено):

1. `LoadLibraryExA("libbz2.dll", 0, 0)` — s_libbz2_dll_0082ef48; при невдачі: повідомлення `"Can't load %s"` (s_Can_t_load__s_0082ef38) у лог DAT_0087cb88 (savedebug).
2. `GetProcAddress` для 8 символів BZ2; результати зберігаються у **глобальні змінні-вказівники** (секція .data, область 0x0088eb44–0x0088eb8c):

| Символ bz2 | Глобал | Семантика |
|---|---|---|
| `BZ2_bzerror` | `_DAT_0088eb4c` | помилка |
| `BZ2_bzclose` | `DAT_0088eb44` | закриття потоку |
| `BZ2_bzflush` | `DAT_0088eb54` | flush |
| `BZ2_bzwrite` | `DAT_0088eb8c` | запис блоку |
| `BZ2_bzread` | `DAT_0088eb88` | читання блоку |
| `BZ2_bzdopen` | `DAT_0088eb68` | відкриття з FILE* |
| `BZ2_bzopen` | `DAT_0088eb84` | відкриття за іменем |
| `BZ2_bzlibVersion` | `DAT_0088eb78` | версія libbz2 |

3. Якщо всі 8 вказівників ненульові — HMODULE зберігається у `*(param_1+8)`, стан `*(param_1+4)=1`, повертає 1; інакше лог `"GetProcAddress failed."` (s_GetProcAddress_failed__0082eeb8) і 0.

Навіщо: сейв-графіка стискається **потоково через bz2** (див. нижче). Викликачі (єдині файли з `BZ2_`/`DAT_0088eb*`): 0x40f6f0 (стиснення), 0x40f920 (розпакування), 0x6f9a20, 0x6f9b00, 0x6f8f00 (обгортки сейву).

## 2. Потокове стиснення/розпакування файлів

Рядки-суфікси (за порядком у .rdata, адреси збігаються з довжинами): `DAT_0082ef88` = ".bz2", `DAT_0082ef90` = ".eug"; поруч `"can't open [%s]"` (0082ef74), `"reason:"` (0082ef6c) і `"Couldn't remove..."` (0082ef95 — видалення тимчасового файлу).

### FUN_0040f6f0 @ 0x40f6f0 — СТИСНЕННЯ (файл → bz2-файл)
- Аргументи: ім'я файлу (без/з розширенням) + прапорець `'\x01'`.
- Будує **два імені** додаванням суфіксів ".eug" і ".bz2"; одне відкриває через `FUN_007a6615` (fopen), інше — через `(*DAT_0088eb84)()` = BZ2_bzopen у режимі запису (або `(*DAT_0088eb68)` = bzdopen, якщо вхід уже FILE* — перевірка магічної константи стека 0xfffffef0).
- Цикл: поки `FUN_007a67c4()` > 0 (джерело даних) → `(*DAT_0088eb8c)()` = **BZ2_bzwrite**; потім `(*DAT_0088eb44)()` = **BZ2_bzclose** і fclose.
- Тобто: текстовий сейв-файл перетворюється у bz2-потік; проміжний файл видаляється ("Couldn't remove...").

### FUN_0040f920 @ 0x40f920 — РОЗПАКУВАННЯ (bz2-файл → файл)
- Те саме два імені ("<ім'я>.eug"/"<ім'я>.bz2"); `BZ2_bzopen` на вхідному, fopen на вихідному; якщо fopen не вдався — `"can't open [%s]"` + `"reason:"` і повернення 0.
- Якщо bz2-потік не відкрився — `"can't bz2openstream"` (0082ef54).
- Цикл читання: `(*DAT_0088eb88)()` = **BZ2_bzread** блоками 0x1000 → `FUN_007a6a0f` (fwrite) розпакованих даних; `BZ2_bzclose`, fclose, повертає 1.

Висновок: сейв-файли DH = **bz2-потоки** з розширенням .eug; гривній текстовий парсер працює з тимчасовим розпакованим файлом ("scenarios\save games\temp.txt" присутній у рядках; посилання в декомпіляції не марковане символом).

## 3. Клас «SaveGameFile» (front-end 0x6f-діапазону)

- **FUN_006f8f00 @ 0x6f8f00** — конструктор об'єкта (робочий розмір ~0x22a, vtable PTR_FUN_007f8320, деструктор FUN_006f9540). Параметр `param_4=='\x01'` → режим **збереження зі стисненням**:
  - шлях: `param_2` або `"%s\%s"` (s__s__s_0083a350) з префіксом мода DAT_00dc3a00;
  - викликає **FUN_006f9b00**; при невдачі зберігає ім'я у `param_1+7` і йде на звичайне відкриття.
  - `param_4==0` → без стиснення, лише відкриття через `FUN_00426f50` + підрахунок розміру (`FUN_00427480/004274e0`) — це шлях завантаження/метаданих.
- **FUN_006f9b00 @ 0x6f9b00** — «зберегти+стиснути»: показує екран очікування **"BZIP COMPRESSING FILE WAIT"** (s_BZIP_COMPRESSING_FILE_WAIT_0086fb8c у `param_1+0x226`), двічі перемальовує (FUN_00583f10), викликає `FUN_0040f5a0()` (завантаження bz2) і `FUN_0040f6f0(ім'я, 1)`; після успіху фіксує фінальне ім'я (`param_1+0x1c` + суфікс DAT_0082ef88). При невдачі — попап **"BZIP COMPRESSION FAILED"** (s_BZIP_COMPRESSION_FAILED_0086fb74).
- **FUN_006f9a20 @ 0x6f9a20** — «завантажити+розпакувати»: `FUN_0040f5a0()` + `FUN_0040f920(ім'я)`; при невдачі попап **"BZIP DECOMPRESSION FAILED"** (s_BZIP_DECOMPRESSION_FAILED_0086fb58) у `param_1+0x220`.

## 4. Текстовий рушій сейвів (мовою HoI2)

- **FUN_00534930 @ 0x534930** — відкриває файл (об'єкт 0x316 байт), конструктор **FUN_00533e40 @ 0x533e40**: шлях префіксується `DAT_00dc3a00` (мод: "%s\%s", s__s__s_00850b10), `FUN_007a6615` = fopen з режимом-структурою; помилка → `"Couldn't open file %s"` (s_Couldn_t_open_file__s_00850b18).
  - `DAT_008390e0` — режим **читання** (усі завантажувачі: сценарії, db, сейви);
  - `DAT_008395a0` — режим **запису** (тільки 0x42ec20 і 0x430110 — збереження).
- **FUN_005362c0 @ 0x5362c0** — **СЕРІАЛІЗАТОР (запис усього світу)**: створює токен-об'єкти (syms: 0xe9=рядок, 0x523, 599 …) і викликає віртуальний «write» з ім'ям файлу; дані гри (країни з DAT_00ab27b4, провінції, події історії тощо) виводяться через нього. Саме сюди йде заголовок сейву.
- **FUN_00535cf0 @ 0x535cf0** — **ЗАВАНТАЖУВАЧ сейву**: парсить верхні блоки; логує в DAT_00850e70-буфер секції `"globaldata "` (s_globaldata_____00850e74), `"country "` (s_country_____00850e60), `"tag = %s"` (s_tag____s_00850e54 — тег країни з DAT_00d0ca90+0x1b), `"ai "` (s_ai_____00850e48); далі котирує всіх країн/провінцій списками.
- **FUN_00535c60 @ 0x535c60** — цикл парсингу «до кінця файлу» (`FUN_00534a40` повертає -1); помилка → `"got a parsing error at line %d"` (s_got_a_parsing_error_at_line__d_00850c60).
- **FUN_00534a40 @ 0x534a40** — диспетчер верхнього рівня токенів сейву/сценарію: `INIT_SCENARIO` (s_INIT_SCENARIO_0083b474, прогрес DAT_00893638), глобальні прапори (0xf7/0x236/0x249/0x246 — помилки `"ERROR : %s %s %s line %d"`), `"history"`-секція (0x259), `"events history"` (0xe8, s_Parsing_events_history_____00850c40), `"slept events"` (0x1f8, s_Parsing_slept_events_____00850c24), `"save_date"` (599), а також **0xe9 = версія сейву** → копіюється у глобальний буфер `DAT_00d6139e`/`DAT_00d6159e` (порівнюється з версією гри).
- Версія: буфер `DAT_00d61394` заповнюється з константи `DAT_0088f28c` (6 байт: "1.05.2", відповідає банеру `"Darkest Hour v 1.05.2 (%s)"`, s_-рядок 0x22429/0085...) — це перший рядок/префікс заголовка сейву; прапорець «STANDARDGAME»/«SCENARIOMISS_INFO» (s_STANDARDGAME_0083b444 / s_SCENARIOMISS_INFO_0083b454) записується при ініціалізації (FUN_0042efb0).

## 5. Точки збереження/завантаження

- **FUN_0042ec20 @ 0x42ec20 = SaveGame(ім'я)**: копіює ім'я у `this+0x10`, `FUN_00534930(ім'я, &DAT_008395a0)` (запис), `FUN_005362c0()` (серіалізація), `FUN_005349a0()` (закриття). Викликається з консольної команди `save` у FUN_006d0ed0 (обробник консольних команд; рядки `"Usage : save <filename>"`, `"scenarios\%s.eug"`).
- **FUN_00430110 @ 0x430110** — завантаження гри після меню: екран завантаження з `gfx\load_1024.bmp` (s_gfx_load_1024_bmp_0083b850); якщо `this+0x11f` («restart»?) — збереження поточної гри у `this+0x10` через `FUN_00534930(&DAT_008395a0)`+`FUN_005362c0`; якщо `this+0x11e` — завантаження: `FUN_0042fa90()` (повний скид світу: країни/провінції/пам'ять), і якщо `this+0x116` — автозавантаження **`temp.eug`** (s_temp_eug_0083b42c) через `FUN_00534930(&DAT_008390e0)`+`FUN_00535cf0`; ім'я файлу санітизується (видалення символів `+ ? *` — FUN_004300c0).
- **FUN_0042e9b0 @ 0x42e9b0** — завантаження сценарію: скидає прапори стану (DAT_00d610dc–e6), версію у DAT_00d61394, країни-лічильники DAT_0087b630-634; створює екран прогресу (DAT_00d37ed0) та світ (DAT_00d685a6, 0x2d0e байт); відкриває сценарій `FUN_00534930(param_2, &DAT_008390e0)`+`FUN_00535c60` (весь парсинг), підтримує `temp.eug` (this+0x11c); потім `FUN_0042fde0()` (валідація) та перевірки наявності країн/техкоманд/лідерів (`DAT_00d77b3a`, `DAT_00d77b4c` → FUN_0076ed00/FUN_0076c940).
- **FUN_0042efb0 @ 0x42efb0 — StartNewGame**: кроки прогресу `INIT_PROVINCES` (s_INIT_PROVINCES_0083b484) → `INIT_SCENARIO` → `INIT_SCRIPT` (s_INIT_SCRIPT_0083b468); `FUN_0042e9b0(this+0x10)`; завантаження db: техкоманди (**FUN_0076c940**: `"Loading Tech Teams (%s)"`, db\tech_teams.csv, s_Loading_Tech_Teams___0087775c), лідери (**FUN_0076f220**: `"Loading Leaders"`/`"Loading Leaders (%s)"`, db\leaders.txt + db\leaders.csv, s_Loading_Leaders___0087855c/00878584); запис STANDARDGAME/SCENARIOMISS_INFO.
- **FUN_0042ecd0 @ 0x42ecd0** — головне меню → нова гра (той самий ланцюг: db + `FUN_0042e9b0`).

## 7. Список сейвів: метадані та перевірка цілісності

- **FUN_0057d7c0 @ 0x57d7c0** (через обгортку FUN_00582330; викликається при побудові списку сейвів): ім'я `"%s.eug"` (s__s_eug_008572a0, з префіксом шляху); відкриває файл (FUN_00426f50), читає по байту (FUN_004271a0), рахуючи **розмір** (`FUN_004274e0`) і **суму всіх байтів** (контрольна сума); результат — об'єкт 12 байт через `FUN_00566590(розмір, ім'я?)`, додається у список (FUN_00565c70).
- **FUN_006f1320 @ 0x6f1320** (меню «Завантажити», case 2): будує шлях `"%s.eug"` або `"%s\%s.eug"` (мод), fopen-перевірка існування; якщо файл є — звіряє **розмір (+0x92)** і **контрольну суму (+0x96)** збережених у записі списку із фактичними; неспівпадіння → об'єкт помилки (FUN_00499310(0x133), слот param_1+0x162) — сейв вважається пошкодженим; при успіху — створює ігровий екран (FUN_006fc370) і вантажить гру. Статуси збереження: `NORMALSAVE`/`QUICKSAVE`/`QUICKLOAD`/`AUTOSAVE` (s_NORMALSAVE_0086667c…) — банери у HUD FUN_0064ad80.
