# Формати мапи Darkest Hour (map/Map_1) — повна реконструкція

Дата: 2026-10-23. Метод: прямий розбір бінарників Python (stdlib), математична перевірка гіпотез,
звірка з `distances.csv`, `Province.csv`, `adj-defs.csv`, логом гри (wine-savedebug.txt) та
рядками/кодом `Darkest Hour.exe` (objdump, адреси-підказки).

Базові константи, ПІДТВЕРДЖЕНО:
- Мапа: **29952×11520 пікселів** (перший запис boundbox.tbl; лог гри).
- Провінцій: **2769 реальних** (Id 1..2769) + PROV0 (Id 0, фіктивний) + «привид» Id=-1 у Province.csv.
  Усього рядків Province.csv = 2771 (включно з Id=-1). Гра читає з airdist «2769 провінцій» (лог).
- Внутрішня сітка мапи: **блоки 32×32 px** — (29952/32)×(11520/32) = 936×360 = 336 960 блоків.

---

## 1. boundbox.tbl — точний формат: ПІДТВЕРДЖЕНО ПОВНІСТЮ

- Розмір: 44 320 Б = **16 Б × 2770**.
- Структура: `uint32 LE` ×4 на запис = `(x1, y1, x2, y2)` — bounding box провінції.
- **Запис 0 = (29952, 11520, 0, 0)** — це bbox провінції PROV0 = розмір всієї мапи.
- Записи 1..2769 — bbox провінцій 1..2769 **у пікселях мапи, але в ПІВ-МАСШТАБІ** (0..14976×5760):
  центр bbox провінції 1 (Ісландія) = (13090, 730), CSV-координати міста = (13159, 749) — збіг ±70 px.
  Повний масштаб = ×2: 2×13090 = 26180 px → lon = 26180/29952×360−180 = −25.4° ✓ (Рейк'явік).
- Перевірено: центри bbox проти координат City X/Y з Province.csv: медіана |dx|=46, |dy|=40 px;
  2118/2769 провінцій у межах 100 px (решта — великі/прибережні, центр не збігається з містом).
- **Обгортання (шив мапи)**: провінція 2405 має bbox (28677, 974, 30539, 2363) — x2 > 29952
  (х→30539−29952=587 з іншого боку). Тобто полігон перетинає межу −180°/+180°.
- Фіктивні провінції 2766–2769 (і 1012, 1159, 2464 — океанічні «світові» моря) мають
  bbox = вся мапа (29952, 11520, 0, 0): їхні «центри» збігаються ⇒ відстані між ними = 0
  (підтверджено airdist: d(2768,2769)=0).

## 2. airdist.tbl — повітряні відстані: ПІДТВЕРДЖЕНО ПОВНІСТЮ

- Розмір: 7 664 594 Б = 2 + 3 832 296×2.
- Структура: **`uint16 LE` заголовок: N = 2769** + **верхній трикутник симетричної матриці
  N×(N−1)/2 = 3 832 296 значень `uint16`** (без діагоналі), рядок за рядком:
  d(a,b), a<b: офсет = T(a) + (b−a−1), T(a) = (a−1)·N − (a−1)·a/2.
- **Семантика: великоколова відстань у КІЛОМЕТРАХ** між центрами провінцій за координатами
  з distances.csv. Звірка на 8000 парах: відносна похибка ~+0.12% (гра рахує радіусом ≈6378 км,
  формула = acos-гаверсин; значення округлюються до цілого).
- Контрольні значення: d(1,2)=741 км (Рейк'явік–Торсгавн, GC 741 ✓), d(1,3)=252 (Рейк'явік–Акурейрі ✓),
  d(4,6)=152 (Сторновей–Інвернесс ✓), максимум 20028 ≈ пів-обводу Землі ✓.
- Якщо файлу немає — гра перераховує його з distances.csv (рядок exe: «airdist.tbl not found!
  Recalculating from %s\distances.csv»).

## 3. navaldist2.tbl — морські відстані: СТРУКТУРА ПІДТВЕРДЖЕНА, склад набору — НЕ ПОВНІСТЮ

- Розмір: 7 617 604 Б = 2+2+7 617 600.
- Структура: **`uint16` = 1380** (кількість «морських провінцій», читається грою: «Done! (%d naval
  provinces, Read distances …»), **`uint16` = 0** (вирівнювання), далі **матриця 1380×1380 `float32`
  LE**, симетрична, діагональ = 0. 1380² × 4 = 7 617 600 ✓.
- **Семантика: морський шлях (≥ великого кола)** у тих самих км, але в одиницях ≈ 1/72.4:
  пара (зона 0, зона 3) = 13.35 → ×72.4 = 966.5 км = точно GC(Рейк'явік→Сторновей) ✓;
  пара (0,5) = 15.43 → 1117.1 км = GC(Рейк'явік→Інвернесс) ✓ (r = 1.000 на відкритих морських парах).
  Для «обхідних» пар значення > GC закономірно (напр. Рейк'явік→Акурейрі навколо півострова: ×4.1 GC).
- **Ідентифікація зон**: зона 0 = провінція 1 (Рейк'явік); перші ~40 зон = провінції 1..41 у порядку
  Id (пропускаючи суходільні). Далі порядок збігається з «Id-порядком набору з 1380 морських
  провінцій», але **точний склад набору (609 океанів + 771 прибережна/портова) не відновлено
  однозначно** з даних: кандидати (море ∪ порти мінус озера) дають 1421, а 1380 = море + 771.
  Ймовірно, гра визначає прибережність за пікселями (а не за adjacent.tbl).
- Файл генерується exe під час завантаження сценарію з distances.csv (моддерська документація).

## 4. adjacent.tbl — суміжність: ПІДТВЕРДЖЕНО ПОВНІСТЮ

- Розмір: 200 096 Б.
- Структура (`uint32` LE): **[0..2769] = 2770 префіксних сум** (офсети списків для провінцій 0..2769),
  **[2770] = 15751** (загальна кількість ребер), далі **15751 записів × 12 Б**: `(uint32 сусід, uint32 0,
  uint32 0xCDCDCDCD)` — третє поле — паддінг (0xCD = «невикористано», заповнювач з інструмента
  генерації; завжди 0xCDCDCDCD, друге поле завжди 0).
- Семантика: неорієнтований граф сусідів для руху **по суші + протоки + прибережні морські зони**
  (ребра море↔суша є: Рейк'явік(1)→2664 (море) ✓; 4394 з 15751 ребер торкаються моря).
  Перевірено: 2699/2770 вузлів, 0 самосуміжностей, асиметрія = 1 пара (2200→1050, море→гора —
  артефакт генератора), Ісландія: 1:{3,2664}, 2:{2676}, 3:{1,2664,2665} ✓, Сторновей(4):{2716} —
  лише протока до Інвернесса(6) ✓ (adj-defs: «4;6;Sea;2716»).
- Провінції з 0 сусідів: {0, 1012, 1159, 2464, 2760..2769} — фіктиви + «глобальні океани».

## 5. index.tbl — індекс РІЧКОВИХ тайлів: СТРУКТУРА ПІДТВЕРДЖЕНА, ПОРЯДОК СТОВПЦЯМИ

- Розмір: 1 347 840 Б = 336 960 × 4 = **один `uint32` на блок 32×32 px мапи** (936×360).
- **Порядок — за стовпцями (column-major)**: зміщення(bx,by) = (bx·360 + by)·4 (рендерер
  0x4DF906: база стовпця bx·0x2D00 / 32 + by). Перевірка: при такому порядку тайли
  складаються у зв'язні річкові системи (70% з'єднань між сусідніми блоками проти 14%
  при row-major). Раніше записаний «порядок (y,x)-сканування» — ХИБНО.
- Значення: **0 = немає річки** (96.7% блоків); **1..11225 — унікальні, кожне рівно один раз**
  (кожен річковий тайл використовується для ОДНОГО блока — річка в кожному блоці своя).
- Семантика: index.tbl + tiles.bmp = **шар річок**, накладений ПОВЕРХ карти з lightmap
  (не атлас місцевості!). Незалежне підтвердження: HoI2-Editor/Zolo84 (див. RE-lightmap.md).

## 6. tiles.bmp — атлас РІЧКОВИХ тайлів: ПІДТВЕРДЖЕНО

- BMP 8 біт з палітрою: 8192×1408 px, 256 кольорів (палітра з байта 54, 256×4 Б;
  bfOffBits = 1078), без стиснення; розмір 54+1024+8192×1408 = 11 535 414 ✓ точно.
- **Тайли 32×32**: сітка 256×44 = 11 264 слоти; 39 слотів повністю порожні (індекс 0)
  → 11 225 реальних тайлів = кількість ненульових значень index.tbl ✓✓.
- **Палітра tiles.bmp ідентична gfx/palette/tile.bmp** (перевірено, 256 записів): запис 0 =
  (0,255,0) — ключ прозорості (піксель не малюється); запис 1 = (255,0,255) (маджента);
  записи 2..~140 — **відтінки води** (47..118: 63,89,97; 61,85,93; 67,93,101; …), не суші!
  (Попередній запис «відтінки суші (оліва/коричні)» — ХИБНО, це був погляд на палітру
  palette-файлів місцевості.)
- Вміст тайлів — **тонкі (1–3 px) лінії річок** (медіана 200 непорожніх пікселів із 1024);
  тайл 0 порожній. Раніше записане «тайли 0..7 = фрагменти узбережжя» — це були фрагменти
  річок у прибережних блоках.

## 7. lightmap1..4.tbl — шари освітлення/текстур на 4 рівнях зума: СТРУКТУРА ПІДТВЕРДЖЕНА, семантика полів — НЕ ПІДТВЕРДЖЕНА ПОВНІСТЮ

- 4 файли = 4 зум-рівні карти (моддерська документація: DH має 4 карти для 4 zoom levels).
- Структура (усі 4 однакова): **[336 961 × `uint32` LE — таблиця зсувів]** (монотонна, від 0;
  перші записи 0,6,12,18,… = розділи по 6 Б; останній = розмір області даних) + **336 960 секцій
  змінної довжини** (по одній на блок 32×32):
  - секції по **6 байт** = стандарт (247 766 з 336 960 у lightmap1; у 4-му рівні більшість секцій 0 Б);
  - секції більші (10,13,17,47,82,163,383,509,613,852… до ~1478 Б) — деталізовані зони
    (кластери в Західній/Центральній Європі; розміри ≠ кратні 3/6 — нагадують RLE-потоки:
    усередині довгі серії 0xFF/0x00/повтори кольорів).
  - вміст 6-Б секції = 2 triples (швидше за все 2×24-бітні кольори: океанічний блок = (98,137,0),(24,0,0));
    точне значення полів не встановлено (потрібен розбір функції завантаження 0x4D8F50 exe —
    вона будує ім'я «%s\lightmap%d.tbl» для 1..4 і читає файл зі зсувною структурою).
- Розміри: 23 850 723 / 20 387 211 / 12 217 962 / 3 536 931 Б — спадання відповідає зменшенню
  деталізації секцій.

## 8. CSV-супутники

- **distances.csv** (2773 рядки): [«2770;Total Provinces;ID;ENG;Region», «Latitude;Longitude;;;»,
  2770 рядків `lat;lon;PROV<id>;EngName;Region`, останній — «EOF;;;;»]. Джерело всіх відстаней.
  Тут же англійські назви (PROV1=Reykjavik, PROV2=Torshavn, PROV5=Scapa Flow…).
- **Province.csv** (2771 рядків, ';'): Id;Name;Area;Region;Continent;Climate;Terrain;…; пункти
  X/Y (місто, армія, порт, пляж, форт, ППО, контр-іконка, terrain-варіант, fill) у пікселях
  повної мапи (0..29952×11520; максимум X=29948); останній стовпець 'X' зі значенням 'X'.
  Терени: Ocean 609, Plains 589, Mountain 513, Hills 355, Jungle 231, Forest 202, Desert 151,
  Urban 66, Marsh 54. Port Allowed=1: 812; Beaches: 465; Port Seazone>0: 812.
- **adj-defs.csv** (1673 рядки): From;To;Type;Through;Comment — 1452 River (додають ребро),
  179 Impassable (прибирають), 38 Sea (протоки, Through = морська провінція), 1 Canal;
  «#END;;;;» і «-1;-1;;;» — термінатори.
- **colorscales.csv**: набір іменованих шкал (Black, Green, …, water, border…): 4 рядки
  `r;g;b;index` з індексами 0, 20, 40, 64 (64 = межа) — градієнти кольорів стратегічної карти.
- **Terrain types.csv**: Number;Type;Movment — 0..11 (Plains 1.0 … Mountain 2.0, Ocean 1.0,
  Terra incognito/Unknown 0).
- **province_names.csv**: `PROV<id>;ENG;FRA;ITA;SPA;GER;POL;POR;RUS…` — багатомовні назви.

## 9. Чи можна намалювати карту — ТАК

Мінімальний набір для відтворення базової карти:
1. **lightmap1..4** — фон: провінції + освітлення (за зумом; RE-lightmap.md §4);
2. **tiles.bmp + index.tbl** — шар РІЧОК поверх (палітра tile.bmp, 0 = прозорий; column-major!);
3. **boundbox.tbl / Province.csv** — полігони провінцій (bbox + координати міст) для кордонів/підписів;
4. Кольори: політичний режим — колір країни (exe-палітра FUN_0044a740 або
   country.csv main color → colorscales), терен — палітра місцевості за типом терену;
5. Імена провінцій — province_names.csv.

Рендер: фон = колір провінції + світло (lightmap), поверх = річковий тайл (пікселі ≠ 0 з
палітри tile.bmp). Помилковий запис «суша = атлас-тайл за index.tbl» скасовано.

## 10. Відкриті питання (чесно)

1. Точний склад 1380 «морських провінцій» navaldist2 (набір «море+прибережні» ≠ 609+1007 з
   adjacent-графа; потрібне піксельне правило гри).
2. Точні поля 6-байтової секції lightmap (імовірно 2 кольори; потрібен розбір 0x4D8F50).
3. Що саме означають «особливі» великі секції lightmap (RLE?): структура схожа на RLE-потоки,
   але формат не доведено.
4. Проекція мапи: y↔lat підігнана лінійно як [75°N..−48°S] (кореляція 0.984 на 12 000 парах),
   але точна формула гри не підтверджена; сама гра використовує distances.csv, тому проекція
   потрібна лише для відмальовування пікселів.
